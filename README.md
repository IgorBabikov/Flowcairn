# Дайте задачу. Увидьте, что действительно сделано.

Flowcairn помогает выполнять сложные задачи разработки в существующем проекте. Вы описываете цель обычным языком. Система выделяет обязательные требования, предлагает план, выполняет разрешенные изменения и проверяет результат. На главном экране видно, что подтверждено, что осталось и почему работа остановилась.

**Задача завершена только тогда, когда для каждого обязательного требования есть подходящая актуальная проверка.** Успешный ответ AI, зеленый этап графа или сам факт изменения файла этого не заменяют.

## Как это работает

| Шаг | Что видите вы |
| --- | --- |
| **1. Задача** | Цель, ограничения и отдельные обязательные требования |
| **2. План** | Конкретные работы, файлы, способы проверки и границы доступа до записи кода |
| **3. Выполнение** | Изменения в отдельной рабочей копии, проверки и замечания |
| **4. Исправление** | Ограниченная повторная работа и новые проверки затронутых требований |
| **5. Результат** | Для каждого требования — выполненная работа, проверка и состояние файлов, к которому она относится |

Если проверка не выполнена или результат изменился после нее, требование снова становится неподтвержденным. Общий статус **PROVEN** появляется только при полном актуальном покрытии обязательных требований без открытых блокирующих замечаний.

[Подробно о выполнении и проверках →](docs/HOW-FLOWCAIRN-WORKS.md)

## Главный экран — задача

Сначала видны цель, ход работы, требования и проблемы. Проверки, изменения, расход AI и граф зависимостей открываются по мере необходимости. Граф помогает исследовать исполнение, но не управляет правами и не решает, завершена ли задача: это делает локальный исполнитель.

> **Пример:** «Добавь форму регистрации с проверкой email и пароля. Сохраняй введенные данные после ошибки и не допускай повторной отправки». Flowcairn разделит это на проверяемые требования. Тест отображения ошибки не подтвердит автоматически защиту от повторной отправки: для нее нужна своя проверка.

## Попробовать

Текущая версия в `main` собирается из исходников. Нужны **Node.js 22**, Git, существующий проект на Node.js и настроенный локальный AI-клиент. На macOS поддерживается Codex CLI; доступность Claude Code и Cursor зависит от установленного и авторизованного клиента. [Платформы и ограничения](docs/INSTALLATION.md).

```bash
git clone https://github.com/IgorBabikov/flowcairn.git
cd flowcairn
npm ci
npm run build
```

Затем из каталога **своего проекта** запустите `node /путь/к/flowcairn/bin/flowcairn.mjs`. Первый запуск покажет настройку и откроет локальный интерфейс. До изменений кода вы увидите план и границы доступа. Проектные команды `test`, `lint`, `typecheck` и `build` включаются только в выбранном режиме проверок.

[Установка и настройка →](docs/INSTALLATION.md) · [Первая задача →](docs/FIRST-TASK.md) · [Пакет в npm](https://www.npmjs.com/package/flowcairn) (версия пакета может отставать от `main`)

## Границы доверия

Flowcairn сохраняет состояние локально, отделяет исходники своего пакета от проекта, ограничивает доступ AI к файлам и требует согласования плана перед изменениями. Неизвестный результат процесса останавливает работу для восстановления. Для незнакомого кода выбирайте проверки в Docker; режим `trusted-local` запускает скрипты с правами вашей учетной записи и требует отдельного согласия.

Статус **PROVEN** относится к записанным требованиям и выбранным способам проверки. Он не означает, что проверены все возможные сценарии или выполнен выпуск в production. Коммит, отправка в Git, публикация и развертывание остаются отдельными действиями.
