# Task-first UI и честная остановка

## Цель

Основной экран Flowcairn показывает задачу, ее текущий этап, доказанный прогресс и следующее действие человека. Граф исполнения, логи, receipts и машинные данные открываются отдельно и не конкурируют с основным сценарием.

## Проверяемый контракт

1. Shell с брендом, действиями и панелью запусков существует с первого кадра. Загрузка заменяет содержимое внутри shell и не меняет его геометрию.
2. Новая задача содержит только заголовок, подробное описание и номер задачи. Пользователь заранее понимает, что сначала будет анализ, а изменения начнутся только после согласия.
3. По умолчанию выбран экран «Задача». На нем сверху видны цель, честный статус, текущий этап, фактический прогресс по завершенным этапам и одно главное действие.
4. Длинное описание задачи показывается один раз, ограничивается по высоте и раскрывается по запросу.
5. Граф и технические детали открываются отдельным вторичным действием. В расширенном режиме допустимы отдельная панель ноды, evidence, история и план.
6. На ноутбуке документ не прокручивается: список запусков и основной контент имеют собственные ограниченные области, при этом основная вертикальная прокрутка у задачи одна.
7. На мобильном панель запусков открывается как отдельный dialog/drawer; task-first контент не вызывает горизонтальную прокрутку.
8. Loader всегда связан с контекстом: загрузка приложения, подготовка задачи, выполнение этапа или остановка. Неизвестная длительность не получает проценты.
9. После команды остановки UI сразу показывает «Останавливаем процесс…». Состояние `stopped` появляется только после подтвержденного завершения. Неподтвержденная остановка отображается как `stop-uncertain` и не разрешает продолжать как после успеха.
10. Пользовательская ошибка на русском объясняет итог, влияние и безопасный следующий шаг. Machine code и исходное сообщение находятся в раскрываемых технических деталях.
11. Старая подтвержденность скрывается при недоступном или нарушенном live snapshot.
12. Светлая и темная темы, клавиатурный focus и reduced motion сохраняют читаемость всех состояний.

## Визуальная приемка

- Laptop 1366×768: крупный заголовок и текущий этап читаются без увеличения; граф не присутствует на стартовой поверхности; шапка и панель запусков не прыгают при загрузке.
- Desktop 1440×900: основной контент использует доступную ширину, но текст остается в читаемой мере; одно главное действие заметнее служебных.
- Mobile 390×844: нет горизонтальной прокрутки, основные кнопки не меньше 44 px, запуски доступны через drawer.
- Состояния loading, running, stopping, stopped и stop-uncertain визуально различимы текстом и структурой, а не только цветом.

## Нефункциональная приемка

Source changes проходят unit/integration UI tests, typecheck, lint и build. Browser screenshots создаются из текущей сборки и проверяются визуально; зеленые тесты без визуальной проверки не считаются завершением.
