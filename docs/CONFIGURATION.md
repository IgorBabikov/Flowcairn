# Профиль проекта

`.flowcairn.json` — проверяемая локальная конфигурация проекта. Она задает правила, а не хранит ключи и не исполняет произвольный shell. Для Codex достаточно `flowcairn init`: по умолчанию он использует выбранную в Codex модель. Для OpenAI API укажите `--model`. После clone уже настроенного проекта достаточно `flowcairn init`: существующий профиль принимается без перезаписи и без повторного выбора модели.

| Поле | Значение |
| --- | --- |
| `version` | Версия schema профиля; сейчас `1` |
| `integrationBranch` | Ветка, от которой выделяются задачи и к которой относится интеграция |
| `packageManager` | `npm`, `pnpm` или поддерживаемый `yarn`; должен соответствовать lockfile проекта |
| `contextPaths` | Дополнительные разрешенные пути чтения, относительно проекта |
| `checks` | Обязательные `typecheck`, `lint`, `tests`, `build` |
| `checkMode` | `none` по умолчанию; `hardened` для Docker-проверок; `trusted-local` только после отдельного согласия |
| `checkScripts` | Проверенный script проекта для каждой включенной проверки |
| `outputPaths` | Каталоги/файлы generated outputs; не исходный код |
| `manifests` | Манифесты и lockfiles для установки зависимостей проверок |
| `skillManifest` | Подходящие project Skills: путь, исходный хеш, этапы и область применения; создается при init |
| `ai.provider` | `codex` или `openai` |
| `ai.model` | Точный ID модели либо `provider-default`, если Codex управляет выбором сам |
| `ai.reviewModel` | Необязательная отдельная модель review |
| `ai.codexPath` | Необязательный абсолютный путь к установленному Codex CLI |
| `ai.baseUrl` | Поле профиля не означает поддержку произвольного сервиса; API-адаптер ограничен официальным endpoint |

Изменения профиля могут аннулировать текущие разрешения и evidence. После изменения создавайте новый актуальный план; не редактируйте hashes сохраненного run.

## Повторная локальная настройка

Профиль можно хранить в Git; credentials и локальное состояние — нельзя. `init` после clone создает исключенную из Git `.ai-orchestrator` и сохраняет исходные bytes профиля. Для этого Flowcairn добавляет свой блок только в локальный `.git/info/exclude`, а не в командный `.gitignore`. Повторный `init` в существующей локальной установке также не редактирует профиль.

Это не команда обновления конфигурации: переданный повторно `--model` не заменяет модель в уже существующем профиле. Для изменений сначала отредактируйте `.flowcairn.json` и проверьте последствия для действующих планов. Неизвестная существующая `.ai-orchestrator` остается причиной отказа, а не кандидатом на автоматическую очистку.

## Обнаружение workspace-манифестов

При создании нового профиля Flowcairn добавляет root `package.json`, lockfile, конфигурацию pnpm при ее наличии и обнаруженные дочерние `package.json`.

- **pnpm:** `packages` в `pnpm-workspace.yaml` имеет приоритет над `package.json.workspaces`.
- **npm:** поддерживаются массив `workspaces` и объект `workspaces.packages`.
- Обнаруживаются совпавшие физические манифесты, видимые Git, включая еще не отслеживаемые. До запуска задачи setup и необходимые исходники нужно сохранить обычным Git-процессом.

Пример pnpm-конфигурации:

```yaml
packages:
  - "{packages,apps}/**"
  - "!packages/experimental"
```

Поддерживаются относительные glob-паттерны, вложенность, варианты в фигурных скобках и отрицательные паттерны с `!`. Исключения имеют приоритет. Абсолютные пути, выход через `..`, dependency/control directories, symlinks и неподдерживаемая или чрезмерная конфигурация отклоняются.

Если подходящий workspace-манифест скрыт `.gitignore`, команда возвращает `WORKSPACES_IGNORED`: снимите игнорирование или явно исключите этот пакет. Не уменьшайте список случайным удалением манифеста из профиля, чтобы скрыть проблему.

При необходимости задайте `--manifests` явно: это **полный список через запятую**, а не дополнение к обнаруженному. Он должен включать root `package.json`, lockfile, workspace-конфигурацию и нужные дочерние манифесты. Например, для проекта ровно с одним pnpm-пакетом:

```text
--manifests package.json,pnpm-lock.yaml,pnpm-workspace.yaml,packages/core/package.json
```

Повторный `init` не пересобирает `manifests` уже существующего профиля. После изменения структуры монорепозитория проверьте и обновите список осознанно; затем подготовьте актуальное окружение проверок и новый план.

## Какие scripts выполняются

| Проверка в профиле | Script проекта |
| --- | --- |
| `typecheck` | `typecheck`, либо `compile`, если он есть в проекте |
| `lint` | `lint` |
| `tests` | `test` |
| `build` | `build` |

При новом `init` Flowcairn обнаруживает conventional scripts, но не включает и не запускает их. Task JSON и браузер не могут передать свой executable или argv. Для непроверенного проекта выберите `hardened`: Docker запускает только зарегистрированные scripts в контейнере. `trusted-local` запускает exact scripts в отдельной worktree с правами вашей учетной записи, поэтому требует отдельного согласия, привязанного к names scripts и профилю. Не используйте этот режим для чужого кода.

## Scope, context и outputs

- `scope` в задаче — область разрешенных изменений.
- `contextPaths` — дополнительные сведения для чтения; это не разрешение записи.
- `forbiddenPaths` — запреты конкретной задачи.
- `outputPaths` — известные результаты инструментов, нужные для корректной оценки изменений workspace.

Не объявляйте `src`, весь репозиторий или папку с секретами как output. Не расширяйте scope только ради прохождения проверки. Секреты, credentials и лишние персональные данные не должны попадать в AI-контекст.

## Выбор модели

В обычном режиме Codex управляет своей моделью сам, а Flowcairn ее не переопределяет. Для OpenAI API укажите модель явно. Отдельная `reviewModel` может изменить характер проверки, но другое имя модели не является доказательством независимости или качества. Проверяйте результат по diff, tests и поведению продукта.

Наличие API-ключа или Codex executable подтверждает только часть подготовки. Доступ к модели и успешный вызов подтверждаются отдельным реальным выполнением.

Если `pnpm-workspace.yaml` содержит только настройки и не содержит `packages`, проект считается одиночным пакетом. Некорректное явно заданное поле `packages` отклоняется.

## Правила качества

[Skills](SKILLS.md) объясняет встроенные рекомендации, подключение существующих инструкций и приоритет правил проекта. `checks` определяет выполнение уже настроенных scripts. Добавление новых тестов и процент покрытия не являются неявными настройками этого списка.

При `flowcairn init` Flowcairn сам подключает до четырех локальных Skills с понятной ролью: контекст проекта, планирование/реализация, тестирование и ревью. Он берет только проверенные `SKILL.md`, сохраняет их хеши и никогда не запускает содержащийся в них код. Нестандартные Skills остаются отключенными. Для отключения рекомендаций используйте `--skills none`; для ручного выбора используйте `--skills name1,name2` вместе с явными `--skill-actions` и `--skill-scope`.

Поздняя перенастройка project Skills через мастер пока не реализована. Повторный `init` сохраняет профиль; он не меняет выбранные инструкции и их применимость незаметно.

## Первый запуск и локальное согласие

`npx flowcairn` запускает настройку, если проект еще не настроен. В Codex основной режим использует его текущую модель и усиление. `npx flowcairn setup` открывает расширенные настройки после закрытия UI.

`ai.modelMode=provider` означает, что Flowcairn не передает Codex модель или усиление и использует настройки самого Codex. `manual` и `auto` предназначены для явно заданной конфигурации. Автоматический выбор между разными моделями требует отдельного согласия и проверенного каталога моделей аккаунта.

`onboarding.testPolicy` определяет сохранение текущего подхода или добавление тестов по задаче. `onboarding.coverage` не назначает порог покрытия автоматически. Уже настроенные обязательные проверки профиля сохраняются.

Разрешение чтения связано с текущим полным профилем и каноническим корнем в приватной записи установки. Одного `readConsent: true` в отслеживаемом JSON недостаточно. Clone и смена AI-конфигурации не переносят согласие незаметно.
