# Возможности и ограничения

PROVEN означает подтверждение обязательной части конкретного Task Contract выбранными способами проверки. Это не формальное доказательство произвольного поведения и не гарантия отсутствия любых ошибок.

## Область применения

Фундаментальные сущности — Task, Requirement, Work, Artifact, Evidence, Finding и Result. Исполнитель работает с существующим программным проектом; Git и собственные npm scripts не обязательны. Универсальный профиль запускает явно зарегистрированные команды установленного инструмента. Это не означает наличие всех компиляторов, зависимостей или готовых verifiers для произвольной задачи. [Профили проверок](CHECK-PROFILES.md).

Задача не становится PROVEN от общего AI-verdict, diff или успешно завершенных этапов. План без Task Contract не имеет основания для PROVEN. Недоступная проверка, неполное покрытие и открытый blocking finding остаются препятствиями завершению.

После автоматической декомпозиции Flowcairn показывает план человеку и начинает автономное исполнение только после его подтверждения. По умолчанию изменения выполняются в текущем каталоге проекта. Отдельную Git worktree можно выбрать для профиля npm scripts (`version: 1`); такой режим требует Git и последующей интеграции результата. Универсальный профиль (`version: 2`) поддерживает только `direct`.

## Платформы и AI

| Область | Граница реализации |
| --- | --- |
| Runtime | Node.js 22; macOS, Linux и нативный Windows |
| Codex / Claude Code / Cursor | Официальный установленный CLI, его авторизация, штатные tools и permission controls; доступность проверяет адаптер |
| Windows | Нативный Node.js 22, локальный диск и системный .NET Framework compiler для Job launcher. UNC paths отклоняются; сетевые диски не поддерживаются. Совместимость конкретного AI CLI проверяется отдельно |
| UI | Локальный браузер и loopback session-ссылка; удаленная многопользовательская авторизация не реализована |
| Учебный AI | Проверенный адаптер Codex 0.156.1/0.157.1 на macOS с Node 22; Claude, Cursor, неизвестные версии и другие ОС не получают неподтвержденное разрешение на генерацию |

Эта таблица описывает условия допуска к запуску. Она не заявляет приемочный прогон каждого сочетания ОС, клиента и версии. Результаты реально выполненных проверок приведены в [VERIFICATION](VERIFICATION.md). `doctor` не вызывает AI и не доказывает доступ к конкретной модели.

Разрешение учебного вызова проверяется отдельно от доступности клиента для реализации. Неизвестная новая версия CLI может выполнять рабочие задачи, но оставаться недоступной для учебной генерации до проверки ее ограничений. Система не переключается незаметно на другого провайдера или старую версию.

Учебный адаптер передает выбранную модель, но пока не передает отдельное переопределение reasoning effort. Настройка усиления рабочих этапов не подтверждает такое же усиление урока. Счетчики токенов и стоимости учебных запросов пока не включены в отчет о ресурсах исполнения; отсутствие этих данных не означает бесплатный вызов.

AI-клиент читает исходный проект напрямую. Flowcairn не создает дополнительную host sandbox и не гарантирует, что внешние tools или scripts не смогут прочитать секрет. На Windows дочерние процессы объединены в Job Object только для управления завершением. Это не файловая песочница. POSIX mode не считается доказательством NTFS ACL; приватность каталогов зависит от прав пользователя. Node.js не дает POSIX-гарантию directory fsync на Windows.

## Проверки и менеджеры пакетов

- `none` не выполняет команды проекта. Новый план без обязательного verifier не получает разрешение на исполнение; это не PASS для требований к поведению.
- `trusted-local` является default и запускает зарегистрированные команды в рабочем каталоге проекта с правами пользователя. Требуется доверие к коду и зависимостям.
- `hardened` сохранен как совместимое имя для того же локального запуска; усиленную изоляцию это имя не обещает. Docker не нужен для установки и новых запусков.
- Поддерживаются npm, pnpm и ограниченный Yarn 4 с `nodeLinker: node-modules`. Bun, Yarn PnP и произвольные расширения менеджера не обходятся.
- Для других стеков используется профиль executable/argv/cwd/inputs/outputs. Инструменты не устанавливаются автоматически; доступность и результаты конкретных сочетаний перечислены в VERIFICATION.

Исполняемые инструменты и объявленные входы проверок хешируются блоками по 256 KiB с проверкой идентичности, размера и EOF. Их обычный учет не имеет фиксированного предела общего объема, числа файлов или глубины. Явно переданный бюджет чтения продолжает действовать; ссылки, секретные входы и подмена не становятся допустимыми.

Новые планы закрепляют определения команд, объявленные входы и исполняемый инструмент. Перед запуском повторно проверяется фактический каталог исполнения, включая выбранный npm script и поддержанную статическую настройку script-shell. Это не атомарный снимок файлов на все время работы процесса и не снимок всей SDK. Команды выполняются с правами пользователя; Flowcairn не перехватывает все их действия.

## Размер задачи и контекста

- До согласования плана естественная постановка допускает до четырех дополнительных этапов самостоятельного исследования, по 16 запросов путей за этап. Executor разрешает только доступные файлы проекта и безопасные новые пути, сохраняя исходные ограничения. Исчерпание бюджета не превращается в PASS.
- Число работ, требований и узлов определяется задачей. Каждый этап сохраняет обязательные проверки и связи требований с evidence. Несколько этапов требуют зарегистрированного исполнимого verifier; большой план не дает права обходить его. Размер одного сериализованного плана и ответа AI остается отдельной рабочей границей.
- Автоматическое исправление ограничено двумя циклами. Срок одного плана составляет от 30 минут до двух часов в зависимости от числа работ; неизвестный исход записи нельзя исправлять бесконечным повтором.
- Review bundle ограничен 512 KiB и не обрезается молча. Полная история review ограничена 20 предыдущими execution-версиями.
- Обычный edit ограничен 128 KiB на файл и 1 MiB на batch. Hash-bound move может переместить большой файл; это не разрешение переписать его сверх лимита.
- Структурный перенос ключей JSON ограничен 8 MiB на файл и 32 MiB на batch. Система сверяет исходные байты, ключи и значения; обычные текстовые правки сохраняют прежний лимит.
- Локальный inventory инструкций и Skills не ограничен фиксированными числом файлов, глубиной, размером файла или общим объемом. Полные хеши и UTF-8 проверяются порциями; bodies не собираются целиком для онбординга. Отмена, ошибка чтения, ссылка или подмена дают явную неполноту. Повторная проверка начинается с актуальных файлов.
- Число зарегистрированных project Skills не ограничено четырьмя. Рекомендация при установке остается небольшим набором известных ролей. К действию применяются только выбранные actions/scope. Большие применимые правила передаются как проверенные private read-only копии с полными hashes, которые CLI должен прочитать частями до EOF. Размер порции/порога inline не отбрасывает остаток. Если полное чтение невозможно, требуется uncertain, а не пропуск правила или PASS.
- Длинная постановка сохраняется целиком; полный текст, acceptance и scope передаются через закрепленный private JSON-файл. Исходный критерий не заменяется первым фрагментом. Ограничения имени задачи и machine IDs не являются пределом объема исходников.
- Учет обычных исходников и fingerprint не имеет прежних отсечек 20 тысяч файлов, 32–64 MiB на файл или 256–512 MiB на проект. Список метаданных занимает память пропорционально числу файлов; содержимое хешируется рабочим буфером. Чтение страницы проверяет весь текущий файл, сохраняя только запрошенное окно. Физические ресурсы ОС и запреты доступа сохраняются.
- Внешний serialized prompt Claude Code/Cursor ограничен 128 KiB до дополнительной оболочки schema. Слишком широкий контекст отклоняется.

Большую задачу следует выполнять проверяемыми этапами. Рабочие порции и модельное окно не означают конечный предел размера проекта. Summary вместо исходного evidence не подтверждает корректность. Проверенный охват и оставшиеся границы перечислены в [аудите](LIMITS-AUDIT.md).

## Учебные источники

Материалы сохраняют выбранные версии текстовых исходников локально в `.ai-orchestrator`, включая содержимое файлов. Это отличается от обычного fingerprint, в котором достаточно хешей. Каталог исключен из устанавливаемого пакета и Git-интеграции; не публикуйте рабочую историю вместе с закрытым кодом.

- Поддерживается полный UTF-8 текст, включая BOM и CRLF. Бинарные файлы, известные секреты и запрещенные пути не включаются в учебный текст.
- Выбранные версии исходников сохраняются целиком без прежних отсечек 64 файлов, 256 KiB на файл и 2 MiB суммарно. Перед публикацией каталога проверяются полный hash и политика секретов. Неизменяемые UTF-8 chunks, индексы chunks и страницы каталогов ограничивают размер отдельного record; ошибка сохранения не превращается в успешный пустой материал.
- Страница кода содержит до 200 строк и 64 KiB. Длинная строка продолжается через явный cursor по символам; последняя часть и EOF доступны. Частичный диапазон не выдается за целую цитату. Старые сохраненные catalogs/chunks остаются читаемыми.
- Цитата привязывается к конкретным строкам и хешу файла. Это подтверждает происхождение текста, но не истинность всех выводов AI или понимание разработчика.
- Полный prompt учебного вызова ограничен 128 KiB транспортом, ответ — 64 KiB. Не помещающийся контекст отклоняется без усечения. Чтение уже сохраненных исходников не требует нового AI-вызова.
- Чтение, закрытие книги и учебные отметки не повышают PROVEN. Ошибка AI-разбора не заменяет результат проверки кода.
- Учебная пауза не продлевает разрешение на исполнение. После истечения срока требуется существующий путь нового плана и согласования.
- Готовый урок и отметки чтения восстанавливаются после перезагрузки браузера. История законченных вопросов пока не имеет отдельного списка в UI: последний ответ доступен в текущем сеансе, но не открывается автоматически после полной перезагрузки. Активный запрос восстанавливается из состояния запуска.

Эффективность чтения и сохранение навыков проверяются отдельно: [личный пилот](LEARNING-PILOT.md).

## Что покрывает актуальность

Runtime проверяет текущее состояние исходников и закрепленный toolchain. Изменение учитываемых исходников консервативно делает старое evidence stale, даже если правка кажется несвязанной.

Generated outputs и внешние системы не покрываются source fingerprint. Безопасные ignored-файлы включаются в source context после классификации. Для них нужен соответствующий verifier или личная приемка по контракту. Review исходников подтверждает наблюдаемые в коде свойства и не означает выполненный browser/device/production сценарий.

Процессы того же пользователя с полным доступом к машине и администратор хоста находятся вне границы изоляции. Проверка структуры зависимостей и lockfile не защищает от произвольной подмены `node_modules` таким процессом. Store рассчитан на локальную файловую систему, не NFS или multi-host.

## Ресурсы и внешние действия

Usage показывается только из реальных counters. Неполный отчет оставляет общую стоимость и токены неизвестными. Для Cursor нормализованного usage сейчас нет. Доказанного универсального ускорения или снижения стоимости для всех проектов не заявляется.

Human acceptance фиксирует решение по требованию и текущему результату. Она не запускает commit, push, merge, публикацию, deploy или оплату. Эти действия остаются отдельным процессом пользователя.

## Защита контекста

Проверки имен и содержимого защищают данные, которые Flowcairn сам включает в prompts, артефакты, правки и logs. Дополнительные пути задаются через `aiDenyGlobs`, например `["private/**", "customer-data/**"]`. `.gitignore` не является политикой секретов. Возможны пропуски и ложные срабатывания.

Broker и адаптеры используют общую политику; применение запретов к native tools зависит от возможностей клиента. Произвольные scripts и внешние инструменты не проходят через глобальный файловый фильтр Flowcairn. Официальный CLI управляет авторизацией; копии credential HOME не создаются.
