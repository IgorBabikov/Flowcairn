# Возможности и границы раннего релиза

Flowcairn из текущего `main` — локальный инструмент для ограниченных задач. Наличие плана, UI, успешных tests или hashes не является обещанием безошибочной AI-разработки.

## Платформы и провайдеры

| Режим | Предпосылки | Граница подтверждения |
| --- | --- | --- |
| Codex adapter | macOS, Codex CLI `0.145.0` или `0.154.0`, настроенная сессия, доступная модель | Изоляция зависит от поддерживаемых CLI permissions и macOS sandbox; выбор активного чата VS Code не считывается; другие версии/ОС не обещаются |
| OpenAI API adapter | Linux или macOS как целевые платформы, собственный API-ключ, доступная модель | Tool-free адаптер; реальный внешний AI E2E на Linux пока не подтвержден |
| Claude Code / Cursor adapter | Linux или macOS, найденный CLI с exact version pin, настроенная provider session и per-plan consent | Synthetic transport tests не доказывают доступ аккаунта, тариф, policy организации или качество реального ответа |
| Checks, новый проект | Не запускаются автоматически | План и AI-этапы не подтверждают выполнение project scripts |
| Checks, `trusted-local` | Node 22, явное согласие, npm/pnpm/Yarn 4 и существующие project scripts | Scripts запускаются с правами пользователя; режим только для известного кода |
| Checks, усиленный режим | Docker Engine, подготовленный образ, npm/pnpm/Yarn 4 project scripts | Container/unit tests не заменяют проверку конкретного приложения и его окружения |
| UI | Современный браузер, локальная session-ссылка | Только loopback control plane; не многопользовательский удаленный сервис |
| Windows | WSL2 на Linux filesystem как целевая среда | Нативный Windows запрещен; реальный WSL2 acceptance пока не выполнен |

Node.js поддерживается в ветке 22. Успешный `doctor` не равен успешному AI-вызову. Наличие API-ключа не означает доступ к конкретной модели; публичный model ID не доказывает доступ вашего аккаунта.

## Что ограничено намеренно

- Один локальный Executor выполняет nodes последовательно. DAG сам по себе не гарантирует безопасную параллельную запись.
- Текстовый intake создает отдельный этап AI-планирования. Compiler поддерживает от 1 до 12 предложенных шагов реализации и добавляет обязательные gates/checks/review. Качество декомпозиции требует оценки человеком; многомесячная автономная разработка не заявляется.
- Review bundle не превышает 512 KiB. Неполное или слишком большое evidence не должно превращаться в зеленый review.
- Обычный AI-edit ограничен 128 KiB на файл и 1 MiB на batch. Большой существующий файл можно только безопасно переместить с hash-bound доказательством; его переработку или слияние нужно разделить на отдельные проверяемые этапы.
- Повторы ограничены policy и числом попыток. AI/write attempt не повторяется автоматически после неизвестного результата.
- Внешние действия не являются неявным продолжением acceptance: commit, push, merge, deploy и оплата требуют отдельного процесса и разрешений.

## Что не доказывают зеленые статусы

| Evidence | Доказывает | Не доказывает |
| --- | --- | --- |
| Hash плана/Skills/receipt | Соответствие данных trusted anchor | Качество решения или независимое происхождение |
| `skillsUsed` | Модель вернула ожидаемые имена инструкций | Что все инструкции правильно применены |
| Review hash acknowledgement | Ответ связан с переданным evidence | Полное прочтение или отсутствие дефектов |
| Tests/build | Конкретные команды завершились успешно | Покрытие требований, browser/voice E2E или готовность production |
| Human acceptance | Зафиксировано решение оператора | Автоматическую публикацию или безопасность любого следующего merge |

Измерений, позволяющих обещать ускорение, меньшую стоимость или рост качества для любого проекта, пока нет. Универсальная оценка «10/10» была бы недостоверной.

## Границы доверия

Процессы того же пользователя с полным доступом к машине и администратор хоста вне изоляции baseline. Store рассчитан на локальную файловую систему, не NFS/multi-host. Local session token не заменяет удаленную авторизацию.

Перед передачей корпоративного или закрытого кода проверьте разрешения владельца данных, условия провайдера и правила организации. Не добавляйте ключи, raw audio и лишние персональные данные в scope или artifacts.

## Ограничения среды проверок

Рабочий каталог Docker-проверки размещается в tmpfs: до 1 GiB и 131072 файловых объектов, с общим лимитом памяти контейнера 2 GiB. `/tmp` ограничен 64 MiB и 16384 файловыми объектами. Зависимости копируются из неизменяемого образа в этот временный каталог. Слишком большой проект может упереться в лимит; это не повод отключать ограничения или запускать непроверенный код на хосте.

Подготовка образа отдельно загружает зависимости и требует свободного места в Docker. Лимиты выполняемой проверки не ограничивают весь Docker daemon, подготовку образа, общий диск и другие процессы пользователя.

Исключенные пути проверяются без различия регистра и с нормализацией Unicode. На Linux это намеренно строже: запрет `src/private` также запрещает `src/PRIVATE`.

Полный повторный security-аудит отдельной сессии GPT-6 Astra был остановлен фильтром платформы. Локальные защитные проверки не заменяют незавершенный аудит; абсолютная безопасность не заявляется.

Расширенный Orchestrator принимает только два локальных вида проверок: `git diff --check` и наличие файла внутри разрешенного scope. Произвольный executable/argv из task JSON запрещен, в том числе при выполнении старого состояния. Основные tests и сборка Graph запускают только зарегистрированные scripts из профиля: по умолчанию в worktree, в усиленном режиме — в Docker.


## Skills и универсальность

Встроенные профили распознают поддерживаемые JS-зависимости, Flutter, явные зависимости ограниченных форматов Python/Go/Maven/Composer и наличие index.html. Наличие index.html — признак маршрутизации, а не проверка содержимого или качества frontend. Другие стеки получают общие инженерные рекомендации. Если frontend и backend используют один общий manifest, определение профиля не заменяет смысловой анализ каждого файла.

Подключается до четырех project Skills с понятными ролями и фиксированными этапами и областями. Неизвестные Skills остаются отключенными до ручной настройки. Один эффективный Skill ограничен 12 KiB, общий текст инструкций — 32 KiB; контекст не обрезается молча. Вспомогательные файлы и scripts Skills автоматически не исполняются и не загружаются. Смысл всех существующих AI-правил не может быть надежно определен одним сканированием имен файлов.

Это не обещание установки без подготовки в любой репозиторий: нужен Node.js для самого инструмента, Git и поддерживаемые команды проверок. Собственные Python/Rust/mobile toolchain adapters, Bun и нативный Windows остаются за пределами подтвержденного исполнения.

Число версий плана ограничено контрактом конкретной задачи. Когда лимит исчерпан, повторное перепланирование недоступно: сохраните результат и начните отдельную задачу для следующего этапа. Этот лимит не отменяется изменением сохраненного JSON. Лимит двух автоматических исправлений и лимит хранения полной истории review — разные ограничения.
