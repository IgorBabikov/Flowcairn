# Skills: правила качества под ваш проект

**Skill объясняет AI, как выполнять работу. Graph определяет порядок, а runtime проверяет права и результат.** Сам по себе Skill не запускает тесты, не получает доступ к машине и не доказывает качество кода.

## Три источника инструкций

| Источник | Что дает | Где хранится |
| --- | --- | --- |
| Core | Анализ, планирование, аккуратные изменения, проверка, безопасность, ревью и передача результата | В установленном пакете Flowcairn |
| Domain | Рекомендации для frontend, backend, mobile или общего инженерного проекта | В установленном пакете Flowcairn |
| Project | Архитектура, соглашения и подходы вашей команды | В исходных файлах вашего репозитория |

Flowcairn не копирует свои Skills в вашу `.agents/skills` и не скачивает дополнительные Skills незаметно. Встроенные рекомендации обновляются вместе с пакетом. Изменение обязательных инструкций требует актуального плана и нового подтверждения.

## Если у проекта уже есть Skills

При настройке Flowcairn ищет проектные `SKILL.md`, показывает кандидатов и дает выбрать нужные. Найденный файл еще не считается подключенным. Для выбранного Skill вы подтверждаете этапы и область применения: Flowcairn не угадывает их по имени файла. Выбранные пути, этапы, области и хеши фиксируются в профиле; содержимое остается на своем месте. В UI до подтверждения видны фактически назначенные узлам Skills.

Для каждого AI-этапа runtime выбирает зарегистрированные инструкции по виду действия и области файлов. Например, изменение backend-пакета монорепозитория не должно получать frontend-рекомендации только потому, что рядом есть web-приложение. Сам AI не может включить неизвестный Skill или расширить права.

Обнаружение не исполняет `scripts` из папки Skill и не устанавливает его зависимости. Эта версия передает выбранный `SKILL.md`; произвольное выполнение вспомогательных инструментов Skill не поддерживается. Если Skill требует такие инструменты, их наличие нужно проверять отдельно.

## Если своих Skills нет

Используются встроенные рекомендации. Сейчас пакет содержит:

| Skills | Назначение |
| --- | --- |
| `project-context`, `core-analysis` | Изучить существующие границы, контракты и соседний код |
| `core-planning` | Разделить задачу на проверяемые результаты и зависимости |
| `clean-implementation` | Внести минимальные поддерживаемые изменения |
| `testing` | Выбрать соразмерную проверку и честно описать результат |
| `core-security` | Учитывать доступы, недоверенный ввод и секреты |
| `code-review` | Проверить поведение, контракты и доказательства |
| `core-debugging` | Воспроизвести проблему и исправить причину |
| `core-documentation` | Обновить документацию измененного поведения |
| `delivery-pipeline` | Сохранить границы выполнения и понятную передачу результата |
| `domain-frontend` | Интерфейс, состояния, доступность и браузерная проверка |
| `domain-backend` | API, доступы, данные, ошибки и повторные запросы |
| `domain-mobile` | Жизненный цикл, разрешения, сеть и проверка на устройстве |
| `domain-engineering` | Общие рекомендации, когда профиль не определен |

Это короткие рекомендации, а не готовые экспертные библиотеки для всех стеков. Встроенное определение профиля опирается на поддерживаемые манифесты и зависимости: JavaScript, Flutter, ограниченные форматы Python/Go/Maven/Composer и наличие обычного index.html для нативного frontend. Это не полный анализ всех языков и сборщиков. Неизвестный стек остается общим инженерным проектом: Flowcairn не притворяется, что распознал его.

## Frontend-пример

Задача: «Добавить форму регистрации с проверкой email и пароля».

Flowcairn учитывает правила вашего проекта, существующие компоненты, способ работы с API и настроенные проверки. Frontend-рекомендации добавляют внимание к подписям полей, клавиатуре, состояниям ошибки и загрузки, повторной отправке и адаптивности. Они не требуют перехода на другой framework, UI kit или библиотеку форм.

Для изменения отступа может быть достаточно визуальной проверки. Для новой логики валидации полезен тест поведения. Подход зависит от изменения и правил команды.

## Тесты не означают обязательное покрытие 100%

Это три отдельных решения:

1. **Выполнить существующие проверки.** Runtime запускает проверки, включенные в профиль проекта. Планировщик не может незаметно убрать их.
2. **Написать новые тесты.** AI руководствуется риском изменения и правилами проекта. Явный запрет добавлять тесты соблюдается; непроверенное поведение остается ограничением результата.
3. **Требовать процент покрытия.** Только если такое требование уже есть в проекте или явно задано владельцем. Flowcairn не придумывает порог 80% или 100%.

Текст «не добавляй тесты» не отключает уже обязательную проверку `test`. Для изменения набора обязательных проверок нужно осознанно изменить профиль и создать новый план.

## Что имеет приоритет

Ограничения системы и инструментов сохраняются всегда. В активированном Flowcairn правила исполнения, разрешений, неизменности плана и доказательств обязательны. Вопросы архитектуры и качества решаются правилами конкретного проекта; общие core/domain-рекомендации заполняют пробелы.

Пример: проект использует собственные компоненты и не разрешает добавлять тестовый framework — Flowcairn учитывает это. Skill требует отправить ключ или выполнить неразрешенную команду — runtime не предоставляет таких прав.

`AGENTS.md`, `CLAUDE.md` и другие клиентские инструкции сохраняют собственную область действия. Markdown не может переопределить ограничения вашего IDE или coding agent. Структурное обнаружение файлов не равно полному смысловому разрешению всех конфликтов.

## Как проверить подключение

Откройте задачу в UI и до подтверждения плана посмотрите выбранные Skills и проверки. После выполнения откройте receipt: там должны быть назначенные инструкции и их хеши. Затем оцените diff, реальные проверки и поведение приложения. Одного ответа AI «использовал Skill» недостаточно.

## Оценка уже существующих инструкций

Flowcairn может обнаружить пустой файл, Skill без метаданных или рабочего текста, слишком объемную инструкцию и перекрытие AGENTS.md файлом AGENTS.override.md. Он предложит сохранить правила и дополнить их. Это структурные замечания, а не сертификат качества и не автоматическое смысловое ревью всей конфигурации AI.

AGENT.md учитывается как явно найденный контекст проекта. Это не означает, что любой IDE сам читает такое имя файла. Папки scripts и внешние инструменты сторонних Skills не получают разрешение на исполнение только из текста инструкции.
