# Как Flowcairn работает внутри

Flowcairn не является чатом с красивым Graph. Graph — исполняемая карта задачи. Runtime использует ее, чтобы решить, какой этап можно запустить, что требует решения человека и что нужно сохранить как доказательство.

## Один пример

Задача: «Добавь форму регистрации с email и паролем».

1. Вы описываете результат обычным языком.
2. AI-анализ получает только разрешенный контекст задачи и возвращает структурированные факты.
3. AI-план предлагает этапы и пути. Runtime проверяет schema, DAG, actions, Skills, permissions и scope, затем создает immutable plan.
4. Вы видите plan и подтверждаете его. До этого момента исходный код не меняется.
5. Executor запускает только готовый узел. AI-реализация возвращает структурированные edits; trusted patch handler проверяет пути и hashes до применения.
6. Зарегистрированные checks и отдельный AI-review создают evidence. Результат и его ограничения попадают в receipts.
7. Вы открываете diff и evidence, затем сами принимаете результат и решаете, создавать ли commit или PR.

## Роли внутри системы

| Роль | Что делает | Чего не делает |
| --- | --- | --- |
| Graph | Хранит этапы, зависимости, gates и контракты успеха | Не исполняет код сам по себе |
| Executor | Проверяет готовность, permissions и результаты; сохраняет state | Не рисует интерфейс и не доверяет AI-статусу без evidence |
| AI-узел | Выполняет одну роль: анализ, plan, реализацию или review | Не выбирает произвольные permissions и shell-команды |
| Orchestrator | В отдельном Git-процессе управляет worktree, кандидатами и интеграцией | Не заменяет Executor в обычном Graph run |
| React Flow | Показывает snapshot и разрешенные capabilities | Не является workflow engine |

## Инструкции для AI

Встроенные инструкции Flowcairn открыты в папке [`skills`](../skills). Runtime назначает их по типу узла:

- анализ и plan: контекст проекта, анализ, планирование, безопасность;
- реализация: чистая реализация, тестирование, delivery, безопасность, документация и отладка;
- review: code review, тестирование и безопасность;
- для frontend, backend и mobile добавляется подходящая domain-инструкция, если проект распознан по manifest.

Это не дает AI дополнительные права. Names и hashes примененных инструкций закрепляются в plan и receipts.

## Локальная память

Flowcairn хранит не неограниченную память диалога, а проверяемые artifacts: анализ, plan, receipts, checks, review, hashes и state. Уточнение plan использует сохраненный анализ. Изменение кода, инструкций или контекста делает прежний plan `stale`, поэтому старый вывод не переносится автоматически.

Эта память не обещает устранить галлюцинации AI. Она уменьшает риск потерять согласованные факты и повторно использовать устаревший вывод. Checks, review и приемка человеком остаются необходимыми.

## Токены и стоимость

Flowcairn уменьшает ненужный контекст: в AI-узел попадают только разрешенные файлы текущего этапа. Анализ сохраняется для уточнения plan, поэтому не запускается повторно без причины. Runtime ограничивает source context 256 файлами и 512 KiB, prompt — 128 KiB, а review evidence — 512 KiB.

Это не гарантирует меньший расход для любой задачи. Сложный Graph может выполнить несколько AI-вызовов вместо одного чата. Текущая версия не показывает provider usage, поэтому не заявляет процент экономии. Будущий Usage receipt должен отображать только числовой usage, который сообщил провайдер: input, output, cached и reasoning tokens.

## Границы безопасности

Flowcairn блокирует неизвестные actions и permissions. Task не передает произвольный shell. Запись ограничена утвержденными путями и hashes. Checks используют зарегистрированные Docker-команды. Неопределенный результат останавливает run вместо небезопасного retry.

Система не заменяет проверку человеком, правила организации и условия AI-провайдера. Прочитайте [SECURITY.md](../SECURITY.md) и [ограничения](LIMITATIONS.md) перед передачей закрытого кода.
