# Первая задача

Сначала выполните [установку](INSTALLATION.md). Откройте терминал в корне своего проекта и запустите:

```bash
npx flowcairn
```

При первом запуске откроется короткая настройка, затем — игровой мир. Оставьте терминал работающим. Войдите в Гильдию или выберите ее через «Карта»: ходьба необязательна.

## 1. Опишите результат

- **Заголовок:** коротко назовите результат, например «Регистрация компании».
- **Полное описание:** поведение, ограничения и критерии успеха.
- **Номер задачи:** номер из трекера или другой понятный идентификатор.

Пример описания:

> Добавь форму регистрации. Нужны имя, email, пароль и подтверждение пароля. Для аккаунта компании дополнительно показывай название и ИНН. Объясняй ошибки рядом с полем, сохраняй введенные значения и не отправляй форму повторно во время обработки. Используй существующие компоненты. Не меняй API и зависимости.

Это пример frontend-задачи; исполнитель и учебные материалы не привязаны к одному языку. Для другого стека заранее зарегистрируйте его [проверки](CHECK-PROFILES.md).

Выберите, когда разбирать результат: **«По этапам»** или **«После всей задачи»**. Нажмите **«Начать анализ»**. Flowcairn изучит проект, выделит требования и предложит план.

Технические файлы система подбирает самостоятельно. Если анализу не хватает контекста, Executor проверяет дополнительные пути и продолжает исследование до подготовки плана. Отдельный выбор файлов нужен только при неразрешимой нехватке данных; обычная задача не требует промежуточных подтверждений путей.

## 2. Проверьте и подтвердите план

Посмотрите, что будет сделано, какие файлы изменятся и как будет проверен результат. Если чего-то не хватает, напишите дополнение в панели плана. Например: «Добавь переключатель видимости пароля, доступный с клавиатуры».

Когда план устраивает, нажмите **«Согласовать и начать выполнение»**. Измененный план нужно подтвердить заново. Если клиент отдельно запросит согласие на передачу данных, проверьте его перед продолжением.

## 3. Дождитесь работы и проверок

Flowcairn выполняет небольшие этапы последовательно. У каждого — свои изменения и проверки. Неуспешная проверка останавливает переход дальше; система может подготовить ограниченное исправление в пределах согласованной задачи.

В режиме «По этапам» после проверенного промежуточного этапа появляется учебная пауза, если впереди есть следующий. После последнего этапа система завершает review/handoff и сохраняет итоговый материал без учебной паузы. В Мастерской можно открыть его сохраненный код либо явно отложить разбор и продолжить работу. Закрытие книги не запускает следующий этап. Пауза сохраняется после перезапуска, но не продлевает срок разрешения на исполнение.

В режиме «После всей задачи» те же проверки проходят без учебных пауз. Итоговый материал связан с финальной версией кода. Старые материалы остаются привязаны к своим версиям: последующие правки не подставляются под прежнее объяснение.

Если потребуется ваше решение или работу не удастся продолжить, на экране появится причина остановки. [Что делать при остановке](TROUBLESHOOTING.md).

## 4. Примите результат

Посмотрите измененные файлы и проверки обязательных требований. Непроверенное требование не считается выполненным. Если нужна личная приемка, выполните указанную проверку и подтвердите ее результат.

После изменения файлов прежние проверки могут потерять актуальность — тогда их нужно повторить. Прочтение материала не подтверждает требование и не заменяет личную приемку. Приемка не создает коммит, PR и публикацию: используйте обычный процесс вашей команды.
