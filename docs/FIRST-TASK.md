# Первая задача: от запроса до принятого результата

Сначала пройдите [установку](INSTALLATION.md), проверьте профиль и выберите исходное состояние: commit или явный снимок первой задачи. Начинайте с одного небольшого результата: например, обработка пустого ввода в существующей функции.

## 1. Поставить ограниченную задачу

Из каталога проекта:

```bash
npx --no-install flowcairn task --id ORCH-001 --goal "Добавить проверку пустого ввода" --scope src --accept "Пустой ввод отклоняется; существующие сценарии проходят" --snapshot
```

Для первого запуска `--snapshot` явно включает текущие отслеживаемые изменения. Новые файлы перечисляются через `--include-untracked path1,path2`; например, новый `package-lock.json`. При чистом checkout `--snapshot` не нужен. Для последующих задач сохраните изменения в Git.

Команда регистрирует задачу и создает запуск и план. **AI еще не запускается.** Вам не нужно вручную редактировать реестр Orchestrator.

Для подробной постановки сохраните `task.json`:

```json
{
  "id": "ORCH-002",
  "goal": "Отклонять пустое имя перед сохранением",
  "instructions": "Найти существующую проверку имени. Добавить обработку пустой строки и строки из пробелов. Сохранить текущее поведение для допустимого имени. Не менять API и зависимости.",
  "scope": ["src"],
  "contextPaths": ["README.md"],
  "forbiddenPaths": [],
  "includeUntracked": [],
  "acceptance": [
    "Пустое имя и пробелы отклоняются существующим способом сообщения об ошибке",
    "Допустимое имя сохраняется как раньше",
    "Есть проверка обоих негативных случаев"
  ],
  "checks": [],
  "resources": [],
  "limits": { "maxAttempts": 2, "maxReplans": 2, "timeoutMs": 600000 }
}
```

Пути должны существовать в вашем проекте. Пример — форма постановки, а не обещание, что в любом репозитории есть функция сохранения имени. Если `task.json` находится в checkout, сохраните его в Git до запуска либо держите файл задания вне репозитория, чтобы сохранить чистый baseline.

```bash
npx --no-install flowcairn task --file task.json
```

`checks: []` не отключает обязательные проверки профиля: ядро добавляет их в план.

## 2. Изучить план и разрешения

```bash
npx --no-install flowcairn ui
```

Выберите новый run. Проверьте цель, разрешенные пути, чтение контекста, модель и обязательные checks. Подтверждение относится к конкретной версии плана. Если постановка слишком широкая, исправьте ее до запуска.

Работа начинается с подтверждения плана, затем идут анализ задачи и внесение изменений. Это разрешение на описанный план и scope; отдельной автоматической декомпозиции большой задачи на десятки исполняемых этапов нет.

## 3. Запустить и наблюдать

После явного подтверждения запускайте разрешенное действие. AI работает в пределах выбранного контекста и возвращает структурированные предложения. Executor проверяет scope и исходные hashes и применяет изменения в выделенном worktree.

Проверки запускаются зарегистрированными командами в Docker. Затем отдельный AI-review оценивает результат. Граф показывает только сохраненное состояние, а не выдуманный процент готовности.

Если появился `failed`, изучите причину. Если появился `uncertain`, не пытайтесь продолжить серию повторов: [порядок восстановления](TROUBLESHOOTING.md).

## 4. Принять результат

До финального решения изучите:

- полный diff и список измененных файлов;
- результаты обязательных checks;
- вывод review и оставшиеся замечания;
- выполнение acceptance вашей задачи.

Успешные checks не заменяют ручную проверку поведения. Для интерфейса откройте измененную страницу; для API воспроизведите нужный запрос. Примите результат только после достаточной проверки.

## 5. Передать код в свой Git-процесс

```bash
npx --no-install flowcairn handoff --run RUN_ID
```

Команда показывает worktree, ветку и измененные файлы; сама она не делает commit или merge. `RUN_ID` возьмите из созданного запуска.

Дальше работайте по правилам своего проекта или поручите своему coding agent проверить точный результат и подготовить commit/PR. Пример поручения:

> Прочитай правила этого проекта. Изучи результат Flowcairn в worktree из handoff: diff, проверки и review. Не включай чужие изменения. Подготовь передачу по нашему Git-процессу. Push и merge выполняй только при наличии моего разрешения.

Если рабочая интеграционная ветка сдвинулась, проверка прежнего результата не автоматически доказывает безопасность нового merge. Не удаляйте worktree или локальное состояние, пока передача не подтверждена.

## CLI вместо интерфейса

Для чтения доступны `status`, `plan`, `receipt`, `artifact`, `events`; для управления — `approve`, `run`, `retry`, `recover`, `replan`, `accept`, `reject`, `stop`. Используйте параметры конкретной команды из `flowcairn --help` и актуальные run/plan/challenge из сохраненного состояния. Не переиспользуйте данные подтверждения другого запуска.

`flowcairn orchestrator ...` — расширенный доступ к очереди, отчетам, проверкам и интеграции. Он не нужен для первого запуска и не отменяет отдельные разрешения на Git-действия.
