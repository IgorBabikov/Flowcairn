# Контракт выполнения задачи

Цель → контракт → требования → план → исполнение → verification → repair → reverification → PROVEN.

Этот документ описывает действующие границы Flowcairn. Markdown сам по себе не выдает права: их проверяют runtime, неизменяемый план и зарегистрированные действия.

## Исходная задача сохраняется

Контракт фиксирует цель, обязательные требования, необязательные улучшения, ограничения, предположения, неизвестные, scope и способы проверки. Требования связаны с конкретной работой. Исправление не может незаметно убрать исходное обязательство или расширить разрешенную область.

Простая ограниченная правка текста может обойтись без отдельного анализа. Риск и сложность определяют строгость проверки, но не отменяют права и критерии завершения.

## Исполнение остается управляемым

AI предлагает план, изменения и оценки. Executor проверяет зависимости, права, неизменность входов и результаты действий. После согласования плана исходники меняются в текущем проекте; отдельная Git-копия используется только при явном выборе режима `worktree`.

Согласование связано с точной версией плана. Для внешнего AI-клиента отдельно подтверждается передаваемый контекст. Повторы ограничены; неизвестный исход не разрешает заново запустить запись.

## Завершение определяется доказательствами

`passed` означает, что этапы исполнения завершены. `PROVEN` требует одновременно:

- для каждого обязательного требования есть выполненная работа и допустимый verification path;
- evidence соответствует текущему проверенному состоянию результата;
- обязательные проверки завершены успешно;
- отсутствуют открытые blocking findings;
- проверено полное покрытие обязательной части контракта.

Заявление AI, наличие diff, общий review pass или число успешных этапов не заменяют эту проверку. Требование с методом `human` подтверждает пользователь отдельным решением, связанным с текущим результатом.

## Ошибки входят в lifecycle

Failed verification создает structured finding. Разрешенный repair сохраняет контракт и права, после чего выполняются новые проверки. Замечание закрывается только более поздним успешным evidence затронутых требований.

Изменение проверенного результата делает прежнее evidence stale. Неизвестная остановка процесса требует recovery. Исчерпание бюджета, повреждение данных и недоступность verifier не превращаются в успех.

## Что видит пользователь

Главный экран показывает задачу, покрытие требований, текущую работу, проблемы, evidence и расход. Каждый вывод можно раскрыть до проверки и receipt. Граф доступен как подробное представление исполнения и зависимостей.

Сертификат завершения вычисляется из сохраненных данных. После потери актуальности его нельзя показывать как подтверждение текущего результата. PROVEN не выполняет commit, push, публикацию, deploy или оплату.
