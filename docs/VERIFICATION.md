# Что проверено

## Кандидат 0.2.0: продуктовый workflow

Проверка 14 сентября 2026 года. Публикация npm подтверждается отдельно от готовности кода.

- Штатный набор: 423 теста, 418 прошли, ошибок нет; пять Docker opt-in сценариев запускаются отдельно.
- Typecheck, lint, сборка, проверка публичного состава и архива прошли. Установочный offline-тест после выбора подготовленного npm-кеша также прошел.
- Отдельно проверены пять настоящих Docker-сценариев: npm/pnpm/Yarn, package binary и native executable, Linux onboarding и запуск готового архива через npm exec.
- В Chromium прошли 55 сценариев: состояния, управление, восстановление, последняя версия плана, mobile/light/dark и reduced motion. Один opt-in smoke пропущен в общем наборе и пройден отдельно на реальном сервисе. Реальный сервис дополнительно проверен отдельным smoke-тестом с ожиданием узлов Graph.

### Реальный AI + Docker цикл

Среда: macOS, Node.js 22.13.1, Codex CLI 0.145.0, модель `gpt-5.6-terra`, ручной режим с низким усилением. Использован отдельный синтетический проект без приватного кода.

1. В задаче FORM-102 Flowcairn создал нативную форму, валидацию, сообщения об ошибках и локальную отправку. Разрешены были четыре файла; тесты и зависимости не менялись. Существующие 18 тестов, lint и сборка прошли.
2. Приемка выявила дефект скрытия полей компании. Он исправлен через уточненный Graph. В браузере проверены скрытие и включение полей, сохранение значений, ошибки и фокус, видимость паролей, блокировка отправки и отсутствие горизонтального переполнения на узком и широком экране.
3. Прогоны выявили ошибки контрактов и восстановления самого Flowcairn: области записи AI, формат read-only ответов, историю review после обновления runtime, продолжение планирования и выбор последней версии. Они исправлены с регрессиями. Это не был один безошибочный прогон.
4. Заключительная задача FORM-103 проверила готовый результат в отдельной копии. После согласования плана AI подтвердил no-op, затем реальные Docker-проверки и отдельное AI-review завершились с `pass`. Все восемь runtime-узлов выполнены, статус — `ready-for-review`; `finalDisposition` остался `null`.
5. Десять проверенных файлов совпали с исходной копией приемки, HEAD корня и worktree одинаков. Автоматического commit, PR, push или принятия результата от имени человека не было.

План завершающего запуска: `66d1490b47764c0a3852c723145610dffbe307f509b65ad21917d8a7ddf4d469`. Review receipt: `719e3de68e05b5f46a82b0f08e0d19256f8c308833d513bd06743187b33e8ff3`.

Скриншот README взят из этого настоящего завершающего запуска. Финальный no-op подтверждает приемочный путь; он не выдается за повторное написание формы с нуля.

## Предыдущий релиз 0.1.1

Версия 0.1.1 исправляет запуск через npm/npx-ссылку. Приведенный ниже AI + Docker цикл выполнен на том же runtime до этого исправления входного CLI; он не выдается за повторный AI-прогон новой версии.

Дата: 13 сентября 2026 года. Это границы проверки первого релиза, а не обещание отсутствия ошибок.

## Установка и выполнение

Пакет собран в `.tgz` и установлен в отдельный каталог с тремя runtime-зависимостями, без dev-зависимостей самого Flowcairn. Проверено совпадение файлов архива с исходниками, наличие собранного ReactFlow, запуск `init`, `doctor`, `task` и `ui`.

На macOS, Node 22.13.1, Codex CLI 0.145.0 и Docker выполнена реальная задача в отдельном специально созданном проекте:

1. Функция нормализации заголовка не объединяла внутренние пробелы. До изменения: два теста не проходили, один проходил.
2. Утвержден план с записью только в `src/title.mjs`; AI вызовы использовали `gpt-5.6-sol`.
3. AI предложил изменение; Executor применил его в отдельном worktree. Файлы тестов не менялись.
4. Зарегистрированная Docker-проверка завершилась с кодом 0; отдельно повторены три теста — все прошли.
5. AI-review вернул `pass` и hash полного переданного review evidence.
6. Граф остановился на финальном решении. После проверки diff результат был принят через CLI, все восемь этапов стали `passed`.
7. `handoff` показал только один измененный файл. Основной checkout остался чистым; автоматического commit, push или deploy не было.

Это настоящий внешний AI-вызов на открытом тестовом коде. Маленький пример подтверждает сквозную связность, но не доказывает надежность на любом большом проекте.

## Автоматические проверки

Проверены domain/runtime invariants, API, permissions, receipts, immutable plans, idempotency, unsafe recovery, установка после clone, npm nested dependencies и pnpm workspace discovery. Выполнены typecheck, lint, сборка и браузерные сценарии. HTTP-тесты запускались с разрешенным loopback-портом; запрет `listen` в sandbox не выдавался за успешный тест.

Изменения прошли независимое ревью. Найденные ошибки установки, выбора контекста и упаковки исправлены до публикации. Проверка production-зависимостей через npm audit не нашла известных уязвимостей на указанную дату.

Текущее состояние CI видно во вкладке [Actions](https://github.com/IgorBabikov/flowcairn/actions). Оно относится к показанному там коммиту.

## Что этим не подтверждено

- Реальный OpenAI API цикл с пользовательским ключом: адаптер проверен автоматическими тестами, но этот live-run выполнялся через Codex.
- Полноценный приемочный прогон на Linux/Windows или на больших корпоративных репозиториях.
- Ускорение работы в процентах, экономия токенов, отсутствие всех ошибок или безусловная независимость AI-review.

Перед применением к важной задаче проверьте [ограничения](LIMITATIONS.md), свой scope, обязательные checks и итоговый diff.
