# Что проверено в текущей рабочей версии

Локальный кандидат `0.4.0` проверен на macOS с Node.js 22.13.1. Проверки подтверждают
перечисленные сценарии, а не качество любого ответа AI и не автоматическое выполнение
всех требований произвольного проекта.

| Проверка | Результат |
| --- | --- |
| Полный `npm test` | 729 успешно; 3 Windows-only теста не запускались на macOS; ошибок и отмененных тестов нет |
| `npm run typecheck`, `npm run lint` | Успешно |
| `npm run build` | Успешно, собран локальный интерфейс |
| `npm run test:ui` | Chromium: 125 успешно; 1 внешний smoke пропущен без `FLOWCAIRN_TEST_URL` |
| `npm run test:proof-browser` | Настоящие WorkflowService, HTTP и Chromium: PROVEN, receipt, live source drift, ручная приемка |
| `npm run check:package` | 151 файл; runtime, Skills, CLI и UI на месте; Docker assets не входят в пакет |
| `npm run check:public` | 414 публичных файлов; обязательные документы, ссылки и базовая проверка приватных данных — PASS |
| Провайдеры | Подготовка прямого доступа Codex/Claude/Cursor, direct/worktree, planning/implementation/review проверена на синтетических проектах |
| Большой review | Bundle до 512 KiB читается по проверенному пути; не помещается целиком в prompt |
| Windows | Добавлен отдельный `windows-latest` CI job с Node 22.13.1, нативными процессами и Job Object; результат публикуется проверкой PR |

В unit/integration входят установка локального npm-архива, режим без Git, обычные
проверки в исходном каталоге, сохранность пользовательских настроек, scope/hash
проверки patch broker, ignored-файлы, общая политика секретов и устаревание evidence.

Браузерные и provider-тесты используют **детерминированные ответы AI**. Файлы,
дочерние процессы и браузер настоящие, но успешная mock-проверка не доказывает
совместимость любой версии CLI, наличие подписки или качество реального inference.

Прямой доступ не является полной изоляцией секретов. Проверки Flowcairn покрывают
его собственный контекст, результаты и артефакты; внешние tools и scripts работают
в рамках прав AI-клиента и пользователя. На Windows Job Object отвечает за
завершение процессов, а не за ограничение файлового доступа.
