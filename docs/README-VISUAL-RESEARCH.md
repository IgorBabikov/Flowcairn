# Визуальное исследование README

Этот файл фиксирует решения для обновления страницы репозитория. Внешние примеры изучены 10 октября 2026 года; чужие изображения, логотипы и код не используются.

## Итоговая тройка

### n8n

[README n8n](https://github.com/n8n-io/n8n/blob/master/README.md)

- Сразу показывает большой banner и настоящий screenshot canvas.
- Одна фраза объясняет продукт, аудиторию и ключевой механизм.
- Возможности названы короткими тезисами, а quickstart оставлен ниже.

**Что переносим в Flowcairn:** один сильный кадр рабочего мира, короткая формула продукта и отдельная полоса «что увидит разработчик».

### Trigger.dev

[README Trigger.dev](https://github.com/triggerdotdev/trigger.dev/blob/main/README.md)

- В первом экране есть логотип, понятное обещание и ссылки на действия.
- Путь от кода задачи к наблюдаемому run объяснен последовательно.
- Trace view показывает, зачем продукт нужен в реальной работе.

**Что переносим в Flowcairn:** демонстрацию полного пути и визуальное доказательство наблюдаемого результата, а не только список фич.

### Langflow

[README Langflow](https://github.com/langflow-ai/langflow/blob/main/README.md)

- После короткого позиционирования идут feature-тезисы с понятными глаголами.
- Отдельно вынесен interactive playground как способ быстро понять продукт.
- Quickstart короткий, а подробности уходят в документацию.

**Что переносим в Flowcairn:** отдельный интерактивный walkthrough, компактную навигацию и быстрый путь к первой задаче.

## Решения для Flowcairn

| Задача посетителя | Решение в репозитории |
| --- | --- |
| За 10 секунд понять продукт | Заголовок про поручение, план, проверку и код; animated walkthrough под шапкой |
| Увидеть рабочий механизм | GIF и интерактивная схема с шестью этапами текущего golden path |
| Понять роль графа | На каждом этапе показана цепочка узлов и зависимостей; отдельно отмечено, что граф принадлежит Executor |
| Быстро запустить | Команда `npx flowcairn` и три ссылки: установка, первая задача, ограничения |
| Не принять макет за live inference | В README и демо явно указано, где walkthrough объясняет контракт, а где показан реальный UI-кадр |

## Фактическая граница продукта

`FACT`: текущие документы и код описывают путь «цель → требования → план → согласование → этап → проверка → материал → архив».

`FACT`: внутренний граф хранится в Executor; UI показывает snapshot и capabilities, ReactFlow в текущем UI не используется.

`FACT`: `PROVEN` требует связи обязательного требования с допустимой работой, проверкой и актуальным evidence.

Проверка публичного URL выполняется после публикации; live inference и понимание новым посетителем остаются отдельными границами.

## Реализация после проверки исходного черновика

Первый черновик содержал только текстовую интерактивную схему. Он не выполнял требование демонстрации продукта: локальная ссылка на HTML в GitHub открывала исходник, а картинка комнаты не показывала UI. Финальная версия заменяет схему записанным сценарием текущего интерфейса и отдельным статическим сайтом GitHub Pages.

| Утверждение | Источник | Наблюдение | Метка | Чего не хватает |
| --- | --- | --- | --- | --- |
| До записи нужно согласование | `QuestPlan.tsx`, `capture.mjs` | До клика файл равен 0; после согласования начинается `ai-implement` | FACT | Проверки других пользовательских сценариев |
| Работа связана зависимостями | `recording.json`, `nodes[].needs` | В записанном execution-плане 6 узлов, каждый раскрывается в демо | FACT | Сценарий не демонстрирует все формы DAG и параллелизм |
| Ошибка проверки не означает успех | `guild-workflow-fixture.mjs`, `recording.json` | Настоящий verify.mjs вернул exit 1 при значении 1, затем exit 0 при значении 2 | FACT | Качество самостоятельного ответа внешнего AI |
| Итог рассчитан Executor | `result.jpg`, `recording.json` | PROVEN и 1/1 требований после проверки и подставного review | FACT | Live provider acceptance не проводилась |
| Изменение кода снимает подтверждение | `stale.jpg`, `recording.json` | После внешней записи 3 coverage становится 0/1, агрегированный proof — FAILED | FACT | Это не гарантия всех внешних эффектов и generated outputs |
| Reader показывает сохраненные bytes | `code.jpg` | Итоговый материал показывает counter.json со значением 2 | FACT | Объяснение AI и эффективность обучения в записи не проверялись |
| Статическая интерактивность работает | `tools/readme-demo/verify.mjs` | Прямые ссылки, переключение кадров, раскрытие узлов, keyboard, mobile, ошибка JSON | FACT | Новая проверка production URL после каждого деплоя |

Golden path демонстрации: задача счетчика → ввод в настоящем UI → анализ и план → согласование → первая неудачная проверка → ограниченное исправление → PROVEN → сохраненный код → потеря подтверждения после изменения файла. Модель и ее ответы подставные на всех AI-этапах; остальная цепочка выполняется действующим runtime в отдельном временном проекте.

В отличие от длинного полного обзора, этот маленький сценарий позволяет увидеть механизм, ошибку и доказательство без монтажа вымышленных данных. Основная бизнес-логика продукта для оформления не изменялась. Проверку понимания за 10–15 секунд следует провести отдельно с новым посетителем; собственная оценка дизайна ее не заменяет.
