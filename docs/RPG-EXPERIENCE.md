# Игровой интерфейс Flowcairn

Этот документ задает визуальный и интеракционный контракт. Наличие макета или ассетов не подтверждает интеграцию с runtime. Состояние, права, проверки и продолжение работы определяет executor; интерфейс только отображает их и передает разрешенные команды.

## Мир и рабочие предметы

Главная поверхность — изометрический мир. Рабочие действия имеют разные игровые формы: разговор с наставником, свиток поручения, журнал задач и раскрытая учебная книга. Один большой бежевый modal для всех локаций этому контракту не соответствует.

Названия и предметы универсальны по языкам: Гильдия принимает задачи, Мастерская показывает выполнение и объяснение, Архив хранит историю. Примеры с формой, CLI, сервисом или конкретным языком не определяют модель мира. Нет обязательного написания кода, классов героя, экономики, наград за клики и отдельных executor-агентов у NPC.

| Поверхность | Игровая форма | Что видно одновременно |
| --- | --- | --- |
| Площадь | Мир, герой, вывески, компактный HUD | Все три здания и доступные дорожки |
| Наставник | Портрет у нижнего края + короткая реплика и варианты ответа | Комната, персонажи, большая часть пола и стола |
| Новая задача / план | Узкий вертикальный свиток справа | Площадь и герой слева; одна цель действия на свитке |
| Выполнение | Небольшой текущий статус и доступная остановка | Мастерская; подробности по явному открытию |
| Архив | Небольшой раскрытый журнал, список слева, выбранная запись справа | Полки и герой; никакой сетки карточек |
| Учеба | Большой двухстраничный кодекс | Наставник и герой слева, книга справа |
| Служебные действия | Компактное игровое меню | Мир вокруг меню; детали открываются отдельно |

Перемещение, открытие двери, закрытие книги, scroll и анимация не запускают работу и не меняют proof. Учебный прогресс отмечается явно и не означает освоение навыка.

## Композиция desktop

Координаты в таблице — CSS pixels при масштабе браузера 100%. Текст не получает perspective transform. Мир сохраняет систему координат и `contain` из `assets/rpg/world.json`; DOM не масштабируется вместе с ним.

| Элемент | 1440×900 | 1280×800 |
| --- | --- | --- |
| Знак и имя проекта | x28 y22, max300×64 | x24 y18, max280×64 |
| Текущее поручение | x1112 y24, w300, h≤100 | x956 y20, w300, h≤100 |
| Разговор: панель | x584 y652, w808, h196 | x488 y574, w744, h180 |
| Разговор: портрет | x434 y614, w190, h238 | x350 y540, w178, h218 |
| Свиток задачи / плана | x942 y114, w470, h705 | x826 y96, w430, h645 |
| Учебный кодекс | x502 y176, w910, h607 | x440 y164, w816, h544 |
| Журнал Архива | x752 y360, w660, h440 | x626 y286, w630, h420 |
| Служебное меню | справа36, снизу94, w330, h≤340 | справа24, снизу94, w330, h≤340 |
| Нижняя навигация | центр, снизу22, h50 | центр, снизу18, h50 |

Эти размеры не являются `transform: scale()` всего интерфейса. Использовать обычные размеры, отступы, ограничение ширины и responsive layout. Поля, кнопки и код сохраняют читаемый размер.

В обычном разговоре панель вместе с портретом закрывает не более четверти desktop viewport. Свиток — примерно четверть; учебная книга может занять до половины. Не затемнять остальной мир плотным backdrop и не размывать его. Ввод в активную modal-поверхность изолируется семантически, а не большой непрозрачной подложкой.

Нижняя навигация скрыта и недоступна под разговором, свитком и книгами. Вместо наложения поверх скрытых кнопок есть явное закрытие и Escape. При возвращении восстанавливаются маршрутный контекст и фокус.

## Материалы и типографика

- Сцена, дерево, ткань, кожа и бумага создают игровую подачу. Текст остается обычным DOM. Никаких текстов, полей, кнопок, статусов или кода, запеченных в PNG.
- Заголовки предметов: Georgia/serif, 24–30px, line-height1.15–1.25. Основной текст: локальный Manrope, 16px/1.55. Реплика наставника: 16–17px/1.5. Код: monospace14px/1.65 с настройкой размера. Подписи/пути: 13–14px, не основной учебный текст.
- Темная разговорная поверхность #202B22, светлый текст #F3E3C3; золотой заголовок #E2C084. Бумага из PNG, текст #302719. Акцент действия #24483D; тонкая медная граница #AD8249. Прямые небольшие углы, без больших скругленных SaaS-карточек.
- Главная кнопка: темно-зеленая, тонкий медный кант, текст14px/650, высота≥44px. Второстепенное действие: прозрачная/темная поверхность, спокойный кант, также≥44px. Орнамент не заменяет подпись и не уменьшает hit area.
- Каждый interactive имеет default/hover/focus/active/disabled/pending/error. Причина недоступности доступна текстом. Loading — короткая надпись реальной операции, без выдуманного процента.
- Видимый focus-ring3px с offset3px; не только слабое изменение золотого оттенка. Провести контрастную проверку финальной реализации с реальными texture backgrounds.

## Наставник

`NpcConversation` — отдельная поверхность, не страница справки. Слева прозрачный бюст из существующего mentor-idle, справа имя, одна реплика до180 символов (обычно две строки), одно основное и одно спокойное вторичное действие. Заголовок24px; вводный маркетинговый заголовок и три абзаца описания продукта запрещены.

Фигура наставника продолжает стоять в комнате; портрет обозначает собеседника. Нельзя заменять персонажа иконкой или карточкой «AI-агент». Речь не генерирует новые права и не скрывает техническую причину блокировки.

| Состояние | Реплика | Действия, только при доступной capability |
| --- | --- | --- |
| Нет задачи | «Начнем с поручения. Опишите задачу в Гильдии.» | «Открыть Гильдию» / «Позже» |
| План готов | «План готов. В Гильдии можно проверить этапы и границы работы.» | «Проверить план» / «Вернуться позже» |
| Анализ идет | «План еще готовится. Здесь можно посмотреть ход работы.» | «Ход работы» / «Закрыть» |
| Выполнение идет | «Работа идет. Отчеты появятся по мере завершения проверок.» | «Ход работы» / остановка, если разрешена |
| Hold, урок готов | «Этап проверен. Разберем, что изменилось и как это работает?» | «Открыть разбор» / «Отложить и продолжить» |
| Hold, урока нет | «Этап проверен. Можно подготовить разбор или продолжить работу.» | «Подготовить разбор» / «Отложить и продолжить» |
| Учебный backend недоступен | «Сохраненного разбора пока нет. План и отчеты задачи доступны.» | «Открыть отчеты» / «Закрыть» |
| Ошибка урока | «Разбор не подготовлен. Результат исполнения сохранен.» | явный разрешенный повтор / продолжение |
| Неизвестный результат | «Результат пока неизвестен. Сначала нужно проверить состояние.» | сверка состояния / отчеты |
| PROVEN | «Результат подтвержден проверками. Можно открыть итоговый разбор.» | разбор, если он доступен / результат |

Если capability отсутствует, не рисовать работающую кнопку. Разбор недоступен — короткая честная реплика, а не большая временная информационная простыня. Отмена разговора не снимает hold.

## Поручение и план

`QuestScroll` использует ui-quest-scroll.png. Это один физический свиток с вариантами содержимого `intake`, `plan`, `clarification`, `permission`. Широкая универсальная книга для этих действий не нужна.

Верх: «Гильдия» или номер поручения, заголовок, закрытие. Середина: один прокручиваемый body. Низ: одно основное действие, всегда вне body и не пересекающее текст. Не показывать отдельную строку из кнопок «Новое / Текущее / Настройки» над свитком: новая задача вызывается в Гильдии, текущие — из журнала, настройки — из служебного меню.

Форма сохраняет реальные обязательные поля и ограничения: title≤160, description3…16000, taskNumber≤80. Подписи «Название», «Что нужно сделать», «Номер задачи». Поля выглядят как запись на бумаге: четкая тонкая нижняя граница и мягкая подсветка ввода; native input/textarea/label, без contenteditable. Placeholder не заменяет label.

Режимы: «По этапам» / «После всей задачи», с native radio и ясной короткой подсказкой. Основная кнопка создания — «Начать анализ». Нельзя до анализа писать «Начать выполнение». При close/Escape черновик остается; повторное открытие не сбрасывает введенный текст.

План — последовательный список без карточек: название этапа, ожидаемое изменение, зарегистрированная проверка. Дополнительные права/передача/инструкции раскрываются в этом же свитке. Итоговая кнопка — «Согласовать и начать выполнение»; длинная подпись переносится, а не уменьшается до нечитаемого размера. Все hashes, revision, challenges и integrity/capability gates сохраняются.

Ошибка поля размещается возле него; при submit focus переходит к сводке ошибки/первому проблемному полю. Expired approval: «Разрешение истекло. Проверьте актуальный план», без старой активной кнопки. Не заменять реальные разрешения декоративной «клятвой» или автоматическим согласием наставника.

## Выполнение, результаты и сообщения

Под QuestTracker обязательна локальная темная подложка/затенение #102219 с opacity0.86–0.95 без скругленной карточки. Статус и подпись действия≥14px: одного text-shadow на светлой кладке недостаточно.

Во время работы показывается комната и один `QuestTracker` сверху справа: короткая цель, реальный статус, одно следующее действие. Связь с сервисом и методы polling не занимают постоянный второй абзац HUD; технические детали открываются по запросу. Остановка остается доступной в tracker и в активной поверхности, когда runtime ее разрешает.

`RuntimeNoticeRibbon` — компактное уведомление с цветным краем, короткой причиной и доступными действиями. Оно закрепляется внутри активной поверхности либо в нижнем углу мира; не занимает всю ширину и не запускает поток одинаковых toast. Серьезная ошибка не исчезает по таймеру. Если текст длинный, подробности раскрываются, но причина и действие видны без раскрытия.

`stopping`, `stopped`, `uncertain`, `stop-uncertain`, `failed`, `stale` остаются разными состояниями. `verified stage` не превращается в PROVEN. Полное подтверждение, ручная приемка требований, receipts и diagnostics берутся из прежнего контроллера и остаются достижимыми через «Отчеты»/«Детали исполнения».

## Учебная книга

`LearningCodex` использует ui-codex.png. Левая страница объясняет выбранный шаг; правая показывает связанный read-only код/данные, происхождение и управление шагами. Большой разворот оправдан чтением, а не используется как контейнер для любого меню.

Заголовок связывает материал с этапом/версией. Содержимое берется из актуального контракта урока: вход, caller, преобразования, output/next, purpose, последствия изменения, ошибки/альтернативы, whole flow. Не превращать книгу в фиксированные frontend-главы или симулятор произвольного кода.

На коде всегда видны relative path, строки, версия/source identity и «Только чтение». Происхождение значений — «Данные запуска», «Данные теста», «Ручная трассировка» или «Учебный пример». Unknown language показывает plain monospace, сохраняя bytes/anchors. Предположение о мотивах не выдается за установленный факт.

Шаги переключаются явными «Назад»/«Далее», без autoplay. «Оглавление» открывает список разделов внутри книги. «Развернуть код» временно использует обе страницы как одну читаемую область с возвратом к объяснению; это не IDE. Длинные строки прокручиваются горизонтально только внутри code block, не на всей странице. Выделение/копирование не запускает никаких команд.

Каждая страница имеет ограниченный body; обязательные действия находятся в отдельной нижней полосе внутри чистой бумажной области. Body не заходит под footer. При длинном материале допускается вертикальная прокрутка страниц; смысловые шаги не превращаются в бесконечную страницу. Размер текста можно увеличить без потери кнопок.

Hold виден в tracker. «Отложить и продолжить» отправляет отдельную runtime-команду и ждет подтверждения; закрытие книги и дочитывание не делают этого. Повтор команды сохраняет operationId при неизвестном network result. В after-task книга открывается по выбору после исполнения, без искусственных учебных пауз.

Устаревший источник: видимая пометка «Предыдущая версия» с причиной; старый code сохраняется, новый файл не подставляется под старое объяснение. Нет source context — указать неполноту. Lesson failure не меняет execution/proof и не блокирует разрешенное продолжение. Нельзя показывать вымышленный урок ради заполнения красивых страниц.

## Журнал и навигация

`QuestJournal` — меньший разворот на фоне Архива. Слева простой список поручений, справа выбранная запись и одно действие открытия. Список не состоит из отдельных закругленных карточек. Строка содержит название, дату/статус и при необходимости отметку «Разбор отложен». Учебное состояние и результат исполнения различаются явно.

Пустой журнал: «Здесь появятся ваши поручения» и «Создать поручение». Loading сохраняет размер разворота. Error показывает повтор загрузки, не пустой успешный архив. Long list прокручивается; выбор записи не отправляет повторное исполнение. «Читали» — самоотметка, не «освоено».

На площади три вывески используют реальные anchors из world.json. Визуально это небольшие темные доски с медным краем, а не одинаковые карточки. Hit areas≥44px; координаты связаны с масштабом мира, не с произвольными viewport percentages.

Нижняя навигация: «Журнал», «Карта», «Настройки» с небольшими предметными знаками книги/компаса/управления. «Карта» возвращает полный мир; внутри нее быстрые команды в Гильдию, Мастерскую, Архив и к наставнику доступны с клавиатуры. Ходьба никогда не обязательна. «Настройки» открывают компактное меню с настройкой проекта, техническими деталями и ссылкой Telegram автора. Не вводить снаряжение/инвентарь без функции.

## Ассеты поверх мира

| Файл | Размер | Использование |
| --- | --- | --- |
| ui-codex.png | 1536×1024 RGBA | Учебная книга и меньший журнал |
| ui-quest-scroll.png | 1024×1536 RGBA | Задача, план, уточнение и разрешения |

Оба PNG имеют настоящую alpha. Коричневые RGB за alpha0 могут быть видны в отдельных image viewers, но не должны появляться при корректном browser compositing. Не flatten на коричневый/бежевый фон и не добавлять непрозрачный div вокруг объекта. Проверять именно поверх реальной сцены.

Рекомендуемые чистые зоны, в долях отображаемого объекта:

- Свиток: heading left30%,right15%,top12.5%; body left/right16%,top26%,bottom15%; footer left/right16%,bottom8.6%. Ремень в верхнем левом углу не перекрывается текстом.
- Книга: left page x9…45.4%, right page x54…89.8%; body y15…72%; footer y74…83%. Не класть текст на шов/кромку. Журнал использует те же страницы, с меньшим содержимым и body y16…84%.
- Mentor portrait — визуальный crop существующего прозрачного mentor-idle в DOM, а не новый персонаж. Никакой растровой подписи имени. Портрет декоративный, имя доступно в dialog heading.

Пути, MIME, integrity/hash и asset allowlist добавляются согласованно при интеграции; отдельный произвольный URL loader не нужен. При ошибке картинки сохранить DOM-содержимое на читаемой простой поверхности с сообщением «Оформление не загрузилось», а не блокировать task control. Это fallback, не основной дизайн.

| LearningCodex / CodeSheet | Saved material, anchors, шаги, чтение/увеличение кода | IDE, исполнение примера, запись project source |
| RuntimeNoticeRibbon | Ошибка/ограничение и реальные действия | Оптимистичный PASS и автоскрытие серьезных ошибок |

Текущий `LocationBook` можно использовать как источник lifecycle поведения, но его единую полноразмерную геометрию требуется убрать. `WorkflowBookContent` разделяется по назначению; нельзя просто вложить прежний `TaskOverview` с теми же карточками в красивую картинку книги. Данные, операции и guards остаются у существующего `WorkflowController`.

## Доступность, узкий экран и движение

- Modal semantics допустимы для разных предметов; одинаковый dialog API не означает одинаковый вид. Одновременно активна одна поверхность, фокус возвращается к trigger; polling не перехватывает фокус и не открывает ее вновь.
- Пока поверхность открыта, движение приостановлено. Escape закрывает только текущую поверхность/деталь, не продолжает execution. Закрытие не сбрасывает форму. Новые сообщения announce один раз, без покадрового aria-live.
- Ниже1180px книжные страницы перестраиваются вертикально, код можно раскрыть. Ниже760px оставлять верхнюю полосу мира примерно140–180px, а рабочий предмет занимает доступную нижнюю часть; не сжимать desktop-разворот до двух столбцов по150px.
- На узком экране разговор — портрет/bust72–96px и реплика в нижней полосе; действия друг под другом. Свиток использует доступную ширину с полями12–16px. Для книги допустимо показать одну страницу/переплет; не perspective-transform текста и не уменьшать body ниже16px.
- При200% zoom/малой высоте viewport читаемость и доступ к закрытию/командам важнее процента видимого мира: обычная прокрутка, footer в потоке, без focus под fixed controls. Сцена остается декоративным контекстом, а все функции доступны через DOM.
- Reduced motion: без полета камеры/перелистывания/дыхания; мгновенный переход. Обычный режим: открытие предмета150–180ms opacity/небольшое появление без наклона текста; нет обязательной драматической анимации.

## Первый вход и приемка

Сохраняется путь `npm install -D flowcairn` → `npx flowcairn` → короткая терминальная настройка → открытие мира. Ссылка [Telegram автора](https://t.me/Babikov_build) необязательна. Нет нового installer, регистрации, обязательной подписки или второго browser wizard. На первой площади достаточно краткого приглашения открыть Гильдию.

Для визуальной приемки сравнивать состояния мира, наставника, intake, plan, running/stop, ошибки, журнала и учебной книги на1440×900 и1280×800; дополнительно узкий экран и200% zoom. Мир виден, предметы различаются, персонажи не закрыты обязательными действиями, текст читается/копируется, alpha не дает прямоугольной подложки.

Функционально повторить прежние intake/approve/stop/archive/settings/diagnostics flows и negative cases. Для learning — отдельно hold/continue/restart/expired/stale/lesson failure. Визуальная композиция на демонстрационных данных не заменяет эти проверки и не доказывает учебную эффективность.
