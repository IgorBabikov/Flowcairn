# Установка и первый запуск

Запускайте Flowcairn в корне проекта, над которым хотите работать. После согласования плана он меняет файлы этого проекта. Git не обязателен.

## Подготовка

- Node.js 22, корневой `package.json` и lockfile вашего проекта.
- npm, pnpm или Yarn 4 с `node_modules`.
- Для Codex и Claude Code отдельная установка CLI не нужна: Flowcairn устанавливает проверенную базовую версию вместе с пакетом. Runtime хранит версии отдельно, при запуске настроенного интерфейса проверяет npm не чаще раза в сутки. Новая версия становится доступной следующим процессам после проверки версии и параметров CLI; текущий процесс сохраняет прежний путь. Сетевая ошибка сохраняет текущую версию. Это локальная проверка совместимости, а не полное тестирование нового релиза или подписанный канал обновлений. При первом запуске понадобится авторизация выбранного CLI.
- macOS, Linux или нативный Windows. Docker и WSL не требуются. Для Windows нужен встроенный .NET Framework C# compiler; Flowcairn сам готовит небольшой launcher для надежной остановки процессов. Если системный компонент недоступен, запуск завершается понятной ошибкой.
- Право передавать выбранные файлы используемому AI-провайдеру.

## Установка

В терминале своего проекта:

```bash
npm install -D flowcairn
npx flowcairn
```

Эквиваленты:

| Проект | Установка | Запуск |
| --- | --- | --- |
| pnpm | `pnpm add -D flowcairn` | `pnpm exec flowcairn` |
| Корень pnpm workspace | `pnpm add -Dw flowcairn` | `pnpm exec flowcairn` |
| Yarn 4 | `yarn add -D flowcairn` | `yarn flowcairn` |

Пакет содержит готовый интерфейс — собирать его самостоятельно не нужно. [Версия в npm](https://www.npmjs.com/package/flowcairn).

## Первоначальная настройка

Первый запуск открывает мастер настройки. Отдельно его можно вызвать командой `npx flowcairn init`.

Если в `AGENTS.md` или `AGENTS.override.md` уже есть валидный блок Flowcairn от старой версии, обновление заменит только этот блок и сохранит остальной текст. Поврежденный или вручную измененный блок останется блокировкой: сначала восстановите его или удалите старую интеграцию после проверки.

Выберите Codex, Claude Code или Cursor. Для Codex модель и усиление можно оставить настройками по умолчанию CLI; отдельная установка Codex не требуется. Авторизуйтесь в официальном CLI. Клиент будет читать нужные файлы напрямую в проекте в пределах собственных разрешений; Flowcairn не копирует его credentials и не отключает permission controls. Подключение правил к существующим инструкциям проекта согласуется отдельно.

Настройки сохраняются в `.flowcairn.json`, данные задач — в `.ai-orchestrator/`. Повторный `init` сохраняет существующую настройку. Копирование профиля в другой каталог не переносит согласие на передачу данных.

Если браузер не открылся автоматически, используйте ссылку из терминала. Оставьте процесс работающим. Эта ссылка дает доступ к вашей локальной сессии — не публикуйте ее.

После первой настройки терминал показывает карточку результата. Внизу находится ссылка «Telegram автора»; для скрытого адреса нужна поддержка OSC 8 в терминале. Цвета отключаются переменной `NO_COLOR`. В CI и при перенаправлении вывода ссылка автора не отображается.

## Проверки проекта

Новый локальный проект использует `trusted-local` и автоматически регистрирует найденные conventional scripts. Режим можно явно изменить через `setup --check-mode`:

- `none` — не запускать. Непроверенные требования останутся неподтвержденными.
- `trusted-local` — запускать зарегистрированные scripts в каталоге проекта с правами пользователя. Используйте доверенный код и зависимости.
- `hardened` — совместимое имя для того же локального режима.

Просмотрите предложенный набор команд. Разрешение добавлять тесты само по себе не разрешает их запуск.

Проверьте доступность runtime:

```bash
npx flowcairn doctor
```

Если нужный CLI или менеджер пакетов недоступен, диагностика покажет причину. Установка сама не запускает scripts проекта. Старые команды `checks prepare` и `bootstrap-checks` больше не нужны и возвращают инструкцию по переходу.

По умолчанию используется исходный каталог. `setup --workspace-mode worktree` выбирает отдельную Git-ветку и рабочую копию для организации изменений, а не защиты секретов.

Дополнительные запреты чтения в broker и обработки данных Flowcairn задаются через `aiDenyGlobs`. Штатные инструменты клиента и произвольные scripts могут обращаться к файлам по собственным правам: эта настройка не гарантирует полную недоступность секретов. [Границы защиты](../SECURITY.md).

## Запуск и изменение настроек

[Первая задача](FIRST-TASK.md): описание → план → согласование → работа и проверки → приемка.

Для изменения настроек остановите процесс Flowcairn и выполните:

```bash
npx flowcairn setup
```

Модели и чтение имеют отдельные настройки. Имена scripts связаны с локальным профилем; эта привязка не является отдельным hash их содержимого; смена конфигурации не выдает новые права старому плану. [Поля профиля](CONFIGURATION.md) · [AI-клиенты](AI-HARNESS-INTEGRATION.md).

## Обновление и удаление

`npx flowcairn update` проверяет метаданные npm самого Flowcairn. Обновления Codex и Claude Code готовятся при запуске настроенного интерфейса и применяются к следующим процессам. `doctor`, `--help`, `--dry-run` не запускают updater. Не прошедшая проверку версия не выбирается. После аварийного завершения updater оставшийся `update.lock` блокирует новые обновления, сохраняя установленный CLI; автоматическое удаление такого lock пока не реализовано. Обновляйте зависимость Flowcairn обычным менеджером пакетов.

После остановки Flowcairn можно предварительно проверить удаление:

```bash
npx flowcairn uninstall --dry-run
npx flowcairn uninstall
```

Удаляются только неизмененные файлы и управляемые блоки установки. Измененные файлы, результаты, история и рабочие копии сохраняются. Зависимость удаляется отдельно: `npm uninstall flowcairn`, `pnpm remove flowcairn` или `yarn remove flowcairn`.
