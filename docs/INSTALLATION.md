# Установка и первый запуск

Запускайте Flowcairn в корне проекта, над которым хотите работать. После согласования плана он меняет файлы этого проекта. Git-репозиторий не обязателен для direct-запуска; установленный Git нужен для полного diff evidence обычных текстовых изменений.

## Подготовка

- Node.js 22 и npm для установки и запуска самого Flowcairn. Исходный проект может использовать другой язык и не обязан заранее иметь `package.json`.
- Для существующего адаптера npm scripts нужны корректные manifests/lockfile и npm, pnpm или Yarn 4 с `node_modules`. Другие инструменты подключаются через [профиль команд](CHECK-PROFILES.md).
- Для Codex и Claude Code отдельная установка CLI не нужна: Flowcairn устанавливает проверенную базовую версию вместе с пакетом. Cursor подключается через установленный официальный Cursor Agent CLI. Runtime хранит версии отдельно, при запуске настроенного интерфейса проверяет npm не чаще раза в сутки. Новая версия становится доступной следующим процессам после проверки версии и параметров CLI; текущий процесс сохраняет прежний путь. Сетевая ошибка сохраняет текущую версию. Это локальная проверка совместимости, а не полное тестирование нового релиза или подписанный канал обновлений. При первом запуске понадобится авторизация выбранного CLI.
- macOS или нативный Windows в текущем выпуске. Linux/WSL сейчас вне целевого релиза. Docker не требуется. Для Windows нужен встроенный .NET Framework C# compiler; Flowcairn сам готовит небольшой launcher для надежной остановки процессов. Если системный компонент недоступен, запуск завершается понятной ошибкой.
- Право передавать выбранные файлы используемому AI-провайдеру.

## Установка

В терминале своего проекта:

```bash
npx flowcairn
```

Первый `npx` может спросить разрешение загрузить пакет. Затем мастер настройки и интерфейс запускаются той же командой. npm хранит Flowcairn и его зависимости в своем кеше; исходники пакета не копируются в ваш проект. В проекте сохраняются только профиль и локальное состояние Flowcairn. Ваши `AGENTS.md`, `package.json` и исходники сохраняются.

Если браузер нужно открыть вручную:

```bash
npx flowcairn --no-open
```

Терминал показывает локальный URL с токеном сессии. Не публикуйте этот URL. Остановить интерфейс можно `Ctrl+C`.

Дополнительно можно закрепить Flowcairn как зависимость проекта. Следующие варианты остаются доступны:

| Проект | Установка | Запуск |
| --- | --- | --- |
| npm | `npm install -D flowcairn` | `npx flowcairn` |
| pnpm | `pnpm add -D flowcairn` | `pnpm exec flowcairn` |
| Корень pnpm workspace | `pnpm add -Dw flowcairn` | `pnpm exec flowcairn` |
| Yarn 4 | `yarn add -D flowcairn` | `yarn flowcairn` |

Пакет содержит готовый интерфейс — собирать его самостоятельно не нужно. [Версия в npm](https://www.npmjs.com/package/flowcairn).

### Что проверено

Fresh-cache установка текущего локального tarball `0.6.0` проверена на macOS arm64, Node.js 22.19.0, npm 8.19.4 и 10.9.3: один вызов `npx` → терминальная настройка → локальный UI, повторный запуск, отказ при чужом состоянии, проекты без Git-репозитория и без `package.json`. CLI Node 16.20.2 и 24.17.0 получают понятное требование переключиться на Node 22.

Авторизация Cursor в этих установочных тестах имитировалась; встроенные Codex 0.156.1 и Claude Code 2.1.198 проверены только командами версии. Вход и AI inference не запускались. Это проверка локального пакета перед публикацией; она не подтверждает установку измененного кода из npm registry. После изменения содержимого пакета проверка повторяется для нового tarball.

Native Windows остается обязательной отдельной ячейкой приемки; реальный Windows fresh-cache прогон пока не выполнен. Linux/WSL не входят в текущий целевой релиз.

## Первоначальная настройка

Первый запуск открывает мастер настройки. Отдельно его можно вызвать командой `npx flowcairn init`.

Если в `AGENTS.md` или `AGENTS.override.md` уже есть валидный блок Flowcairn от старой версии, обновление заменит только этот блок и сохранит остальной текст. Поврежденный или вручную измененный блок останется блокировкой: сначала восстановите его или удалите старую интеграцию после проверки.

Выберите Codex, Claude Code или Cursor. Для Codex модель и усиление можно оставить настройками по умолчанию CLI; отдельная установка Codex не требуется. Авторизуйтесь в официальном CLI. Клиент будет читать нужные файлы напрямую в проекте в пределах собственных разрешений; Flowcairn не копирует его credentials и не отключает permission controls. Подключение правил к существующим инструкциям проекта согласуется отдельно.

Настройки сохраняются в `.flowcairn.json`, данные задач — в `.ai-orchestrator/`. Повторный `init` сохраняет существующую настройку. Копирование профиля в другой каталог не переносит согласие на передачу данных.

Если браузер не открылся автоматически, используйте ссылку из терминала. Оставьте процесс работающим. Эта ссылка дает доступ к вашей локальной сессии — не публикуйте ее.

После первой настройки терминал показывает карточку результата. Внизу находится ссылка «Telegram автора»; для скрытого адреса нужна поддержка OSC 8 в терминале. Цвета отключаются переменной `NO_COLOR`. В CI и при перенаправлении вывода ссылка автора не отображается.

## Проверки проекта

Новый локальный проект использует `trusted-local`. Для npm scripts автоматически предлагаются найденные conventional scripts. Служебный `package.json`, появившийся при установке Flowcairn, не превращает Python, C или другой проект в JavaScript-проект. Команды другого стека регистрируются через [профиль проверок](CHECK-PROFILES.md); без выбранной обязательной проверки выполнение остается заблокированным. Режим можно явно изменить через `setup --check-mode`:

- `none` — не запускать. Непроверенные требования останутся неподтвержденными.
- `trusted-local` — запускать зарегистрированные команды в каталоге проекта с правами пользователя. Используйте доверенный код и зависимости.
- `hardened` — совместимое имя для того же локального режима.

Просмотрите предложенный набор команд. Разрешение добавлять тесты само по себе не разрешает их запуск.

Проверьте доступность runtime:

```bash
npx flowcairn doctor
```

Если нужный CLI или менеджер пакетов недоступен, диагностика покажет причину. Установка сама не запускает scripts проекта. Старые команды `checks prepare` и `bootstrap-checks` больше не нужны и возвращают инструкцию по переходу.

По умолчанию используется исходный каталог. Для профиля npm scripts (`version: 1`) команда `setup --workspace-mode worktree` выбирает отдельную Git-ветку и рабочую копию; нужны Git и последующая интеграция результата. Универсальный профиль (`version: 2`) поддерживает только `direct`. Worktree организует изменения и не является защитой секретов.

Дополнительные запреты чтения в broker и обработки данных Flowcairn задаются через `aiDenyGlobs`. Штатные инструменты клиента и произвольные scripts могут обращаться к файлам по собственным правам: эта настройка не гарантирует полную недоступность секретов. [Границы защиты](../SECURITY.md).

## Запуск и изменение настроек

[Первая задача](FIRST-TASK.md): описание → план → согласование → работа и проверки → приемка.

Для изменения настроек остановите процесс Flowcairn и выполните:

```bash
npx flowcairn setup
```

Модели и чтение имеют отдельные настройки. Новые планы связывают команды с выбранными входами конфигурации и инструментами. Изменение этих данных требует актуального плана и согласования; настройки не выдают новые права старому плану. Это не снимок всех зависимостей SDK. ## Обновление и удаление

`npx flowcairn update` проверяет метаданные npm самого Flowcairn. Обновления Codex и Claude Code готовятся при запуске настроенного интерфейса и применяются к следующим процессам. `doctor`, `--help`, `--dry-run` не запускают updater. Не прошедшая проверку версия не выбирается. После аварийного завершения updater оставшийся `update.lock` блокирует новые обновления, сохраняя установленный CLI; автоматическое удаление такого lock пока не реализовано. Обновляйте зависимость Flowcairn обычным менеджером пакетов.

После остановки Flowcairn можно предварительно проверить удаление:

```bash
npx flowcairn uninstall --dry-run
npx flowcairn uninstall
```

Удаляются только неизмененные файлы и управляемые блоки установки. Измененные файлы, результаты, история и рабочие копии сохраняются. Зависимость удаляется отдельно: `npm uninstall flowcairn`, `pnpm remove flowcairn` или `yarn remove flowcairn`.
