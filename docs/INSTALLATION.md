# Установка Flowcairn в свой проект

Flowcairn устанавливается как инструмент разработки. Его пакет и исходники вашего проекта — разные каталоги. Работа выполняется в отдельных worktrees; исходный checkout остается точкой управления.

## До установки

Проверьте:

- Node.js версии 22 и Git доступны в терминале.
- Проект уже является Git-репозиторием с начальным commit.
- Используется npm или pnpm, есть lockfile и scripts для нужных проверок. Для Docker lockfile должен входить в Git-снимок проекта; игнорируемый lockfile не переносится автоматически.
- Docker Engine работает; есть место для образа, зависимостей и временных контейнеров.
- Вы вправе передавать выбранный код выбранному AI-провайдеру. Для рабочего репозитория сначала проверьте политику компании.

Первую попытку лучше выполнить на небольшом открытом или учебном проекте. Выбирайте задачу с одним проверяемым результатом.

## Установить текущую версию

В корне проекта на macOS:

```bash
npm install --save-dev "git+https://github.com/IgorBabikov/flowcairn.git#main" --ignore-scripts
npx --no-install flowcairn init
```

На Linux вместо обычного `init` выполните `npx --no-install flowcairn init --provider openai`; без TTY добавьте `--model MODEL_ID`. Затем настройте API-ключ, как описано ниже.

Для pnpm используйте `pnpm add -D "git+https://github.com/IgorBabikov/flowcairn.git#main" --ignore-scripts`, затем `pnpm exec flowcairn init`.

Готовый интерфейс входит в Git. Сборка при установке и lifecycle scripts не нужны. Lockfile фиксирует Git-коммит: коллеги получают его через обычный `npm ci` или принятый pnpm-процесс. Сохраняйте package.json и lockfile по правилам своего проекта.

Это версия из `main`, а не новый GitHub Release и не npm registry. Старый [релиз 0.1.1](https://github.com/IgorBabikov/flowcairn/releases/tag/v0.1.1) сохранен, но не включает текущие улучшения. Не устанавливайте одноименный сторонний пакет.

В обычном терминале `init` спросит точный ID вашей модели. На macOS по умолчанию используется Codex; для OpenAI API укажите `--provider openai`. Без интерактивного терминала укажите `--model` явно. Flowcairn не угадывает доступные вашему аккаунту модели и не читает глобальные настройки с секретами. Для скриптов есть `--json`.

## Выбрать AI-провайдера

### Codex CLI

Текущий адаптер рассчитан на **macOS и Codex CLI 0.145.0**. Нужна уже настроенная локальная сессия Codex.

```bash
npx --no-install flowcairn init --provider codex --model MODEL
```

Замените `MODEL` на точный доступный вашему аккаунту ID. Если Codex установлен в нестандартном месте, укажите `ai.codexPath` в профиле: [конфигурация](CONFIGURATION.md). Не включайте обход sandbox ради запуска.

### OpenAI API

```bash
npx --no-install flowcairn init --provider openai --model MODEL
```

Здесь нужен **собственный API-доступ**, а расходы относятся к вашему аккаунту провайдера. Настройте переменную `FLOWCAIRN_OPENAI_API_KEY` локально через принятый у вас способ управления секретами. Не вставляйте ключ в команду, `.flowcairn.json`, task JSON, Git, issue или скриншот. Запускающий Flowcairn процесс должен получить эту переменную в своем окружении.

Для одной сессии в Bash или Zsh можно ввести ключ скрыто:

```bash
read -r -s FLOWCAIRN_OPENAI_API_KEY
export FLOWCAIRN_OPENAI_API_KEY
```

После первой команды вставьте ключ и нажмите Enter: символы не отображаются. Запускайте Flowcairn из того же терминала. Значение не записывается в текст команды или профиль проекта. Для удаления из окружения используйте `unset FLOWCAIRN_OPENAI_API_KEY`.

Адаптер обращается к официальному OpenAI endpoint. Модель получает ограниченный набор данных; tools и shell у нее отсутствуют. Возможность вызова конкретной модели зависит от аккаунта. Проверка наличия настроек не доказывает успешную авторизацию или доступ модели.

Linux/macOS — целевые платформы API-адаптера; реальный внешний AI-сценарий на Linux пока не подтвержден. [Матрица ограничений](LIMITATIONS.md).

## Проверить профиль и окружение

`init` создает `.flowcairn.json` и добавляет исключение локального состояния в `.gitignore`. Он не заменяет `AGENTS.md`, hooks и ваши правила Git. При конфликте конфигурации сначала разберите различия; не удаляйте файл только ради повторной установки.

```bash
npx --no-install flowcairn doctor
npx --no-install flowcairn checks prepare
```

`doctor` проверяет доступные предпосылки. Он не равен полному AI E2E. `checks prepare` отдельно подготавливает Docker-окружение проверок; при подготовке могут загружаться образ и зависимости. Обычный run не должен незаметно устанавливать пакеты или переключаться на host shell.

Прочитайте `.flowcairn.json`: integration branch, package manager, context, checks, manifests и output paths должны соответствовать вашему проекту. Не помечайте исходный код как build output. [Описание полей](CONFIGURATION.md).

Для **первой** задачи есть два пути: сохранить изменения установки в Git или явно разрешить локальный исходный снимок флагом `task --snapshot`. Снимок сохраняет текущее состояние отслеживаемых файлов; автоматического коммита нет. Новые файлы нужно перечислить через `--include-untracked`, кроме файлов установки с совпавшими хешами. Например: `--include-untracked package-lock.json`, если новый lockfile не отслеживается Git.

Перед `--snapshot` проверьте `git diff` и `git status`. Снимок и граф сами по себе не разрешают AI-вызовы или запись. **Следующие задачи требуют чистого checkout**. Первый снимок не превращается в автоматический способ скрывать произвольные изменения.

## После clone уже настроенного проекта

Если `.flowcairn.json` уже хранится в Git, после clone восстановите зависимости проекта обычным способом (`npm ci` или принятым в проекте pnpm-процессом), затем выполните:

```bash
npx --no-install flowcairn init
npx --no-install flowcairn doctor
```

Повторно указывать `--model` и `--provider` не нужно: Flowcairn принимает существующий проверенный профиль и создает только локальное состояние в `.ai-orchestrator`, исключенное из Git. Содержимое `.flowcairn.json` сохраняется байт в байт. Если правило исключения уже есть в отслеживаемой `.gitignore`, этот файл также остается без изменений и после настройки checkout остается чистым. Если правила нет, `init` добавит его: проверьте и сохраните это изменение до задачи.

Уже настроенный локальный checkout повторный `init` не перенастраивает. Если `.ai-orchestrator` существует, но не принадлежит этой установке, команда останавливается с конфликтом и сохраняет чужое состояние. Не удаляйте каталог автоматически ради продолжения.

Модель и другие настройки меняются осознанной правкой профиля, а не повторным `init --model ...`. После смены правил нужен новый актуальный план. Docker-образ и credentials на новом компьютере проверяются отдельно; наличие профиля в Git их не восстанавливает.

## npm и pnpm workspaces

При создании нового профиля `init` обнаруживает манифесты workspace-пакетов. Для pnpm источником списка служит `packages` в `pnpm-workspace.yaml`; дублировать его в `package.json` не требуется. Для npm используются `workspaces` или `workspaces.packages` в `package.json`.

Поддерживаются ограниченные относительные glob-паттерны, вложенные каталоги и явные исключения. Совпавший с паттерном, но игнорируемый Git `package.json` не пропускается молча: настройка останавливается. Сделайте такой манифест доступным Git либо явно исключите пакет из workspace-паттернов. Опасные пути и ссылки также отклоняются.

Перед сохранением setup проверьте полный список `manifests` в `.flowcairn.json`, особенно в монорепозитории. [Примеры и явная настройка](CONFIGURATION.md#обнаружение-workspace-манифестов).

## Открыть интерфейс

```bash
npx --no-install flowcairn ui
```

Откройте напечатанную ссылку. По умолчанию сервер слушает только `127.0.0.1:4329`. Другой проект или порт задаются явно:

```bash
npx --no-install flowcairn ui --root PROJECT --port 4330
```

`PROJECT` — путь к нужному репозиторию. Не передавайте ссылку с `session` другим людям и не публикуйте терминал с ней. Подробнее: [первая задача](FIRST-TASK.md).

## Запуск из исходников

```bash
git clone https://github.com/IgorBabikov/flowcairn.git
cd flowcairn
npm ci --ignore-scripts
npm run build
```

Пакет запускается через `node bin/flowcairn.mjs`. Для работы с другим репозиторием используйте абсолютный путь к этому файлу и `--root PROJECT`; не копируйте runtime в исходники проекта вручную. Например, из каталога Flowcairn:

```bash
node bin/flowcairn.mjs doctor --root PROJECT
node bin/flowcairn.mjs ui --root PROJECT
```

Отсутствующие предпосылки сначала устраняйте по выводу `doctor`. Установка на другую ОС сама по себе не подтверждает поддержку ее sandbox.
