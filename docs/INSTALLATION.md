# Установка Flowcairn в свой проект

Flowcairn устанавливается как инструмент разработки. Его пакет и исходники вашего проекта — разные каталоги. Работа выполняется в отдельных worktrees; исходный checkout остается точкой управления.

## До установки

Проверьте:

- Node.js версии 22 и Git доступны в терминале.
- Проект уже является Git-репозиторием с начальным commit.
- Используется npm или pnpm, есть lockfile и scripts для нужных проверок.
- Docker Engine работает; есть место для образа, зависимостей и временных контейнеров.
- Вы вправе передавать выбранный код выбранному AI-провайдеру. Для рабочего репозитория сначала проверьте политику компании.

Первую попытку лучше выполнить на небольшом открытом или учебном проекте. Выбирайте задачу с одним проверяемым результатом.

## Установить пакет релиза

В каталоге проекта:

```bash
npm install --save-dev https://github.com/IgorBabikov/flowcairn/releases/download/v0.1.0/flowcairn-0.1.0.tgz
```

Для pnpm-проекта используйте его менеджер:

```bash
pnpm add -D https://github.com/IgorBabikov/flowcairn/releases/download/v0.1.0/flowcairn-0.1.0.tgz
```

Это tarball GitHub Release `v0.1.0`, не команда установки опубликованного npm-пакета. Проверьте имя репозитория и версию перед установкой. Если asset недоступен, не подменяйте его одноименным сторонним пакетом: проверьте [релиз](https://github.com/IgorBabikov/flowcairn/releases/tag/v0.1.0).

Дальше примеры используют `npx --no-install`: команда запускает уже установленный Flowcairn и не должна искать новый пакет в registry.

## Выбрать AI-провайдера

### Codex CLI

Текущий адаптер рассчитан на **macOS и Codex CLI 0.145.0**. Нужна уже настроенная локальная сессия Codex.

```bash
npx --no-install flowcairn init --provider codex --model MODEL
```

Замените `MODEL` на точный доступный вашему аккаунту ID. Если Codex установлен в нестандартном месте, укажите `ai.codexPath` в профиле: [конфигурация](CONFIGURATION.md). Не включайте обход sandbox ради запуска.

### OpenAI API

```bash
npx --no-install flowcairn init --provider openai --model MODEL
```

Здесь нужен **собственный API-доступ**, а расходы относятся к вашему аккаунту провайдера. Настройте переменную `FLOWCAIRN_OPENAI_API_KEY` локально через принятый у вас способ управления секретами. Не вставляйте ключ в команду, `.flowcairn.json`, task JSON, Git, issue или скриншот. Запускающий Flowcairn процесс должен получить эту переменную в своем окружении.

Для одной сессии в Bash или Zsh можно ввести ключ скрыто:

```bash
read -r -s FLOWCAIRN_OPENAI_API_KEY
export FLOWCAIRN_OPENAI_API_KEY
```

После первой команды вставьте ключ и нажмите Enter: символы не отображаются. Запускайте Flowcairn из того же терминала. Значение не записывается в текст команды или профиль проекта. Для удаления из окружения используйте `unset FLOWCAIRN_OPENAI_API_KEY`.

Адаптер обращается к официальному OpenAI endpoint. Модель получает ограниченный набор данных; tools и shell у нее отсутствуют. Возможность вызова конкретной модели зависит от аккаунта. Проверка наличия настроек не доказывает успешную авторизацию или доступ модели.

Linux/macOS — целевые платформы API-адаптера; реальный внешний AI-сценарий на Linux пока не подтвержден. [Матрица ограничений](LIMITATIONS.md).

## Проверить профиль и окружение

`init` создает `.flowcairn.json` и добавляет исключение локального состояния в `.gitignore`. Он не заменяет `AGENTS.md`, hooks и ваши правила Git. При конфликте конфигурации сначала разберите различия; не удаляйте файл только ради повторной установки.

```bash
npx --no-install flowcairn doctor
npx --no-install flowcairn checks prepare
```

`doctor` проверяет доступные предпосылки. Он не равен полному AI E2E. `checks prepare` отдельно подготавливает Docker-окружение проверок; при подготовке могут загружаться образ и зависимости. Обычный run не должен незаметно устанавливать пакеты или переключаться на host shell.

Прочитайте `.flowcairn.json`: integration branch, package manager, context, checks, manifests и output paths должны соответствовать вашему проекту. Не помечайте исходный код как build output. [Описание полей](CONFIGURATION.md).

После проверки сохраните изменения установки своим обычным Git-процессом. **До создания задачи нужен чистый checkout**: незакоммиченные изменения не должны случайно потеряться при выделении worktree. Flowcairn не делает этот commit за вас.

## Открыть интерфейс

```bash
npx --no-install flowcairn ui
```

Откройте напечатанную ссылку. По умолчанию сервер слушает только `127.0.0.1:4329`. Другой проект или порт задаются явно:

```bash
npx --no-install flowcairn ui --root PROJECT --port 4330
```

`PROJECT` — путь к нужному репозиторию. Не передавайте ссылку с `session` другим людям и не публикуйте терминал с ней. Подробнее: [первая задача](FIRST-TASK.md).

## Запуск из исходников

```bash
git clone https://github.com/IgorBabikov/flowcairn.git
cd flowcairn
npm ci
npm run build
```

Пакет запускается через `node bin/flowcairn.mjs`. Для работы с другим репозиторием используйте абсолютный путь к этому файлу и `--root PROJECT`; не копируйте runtime в исходники проекта вручную. Например, из каталога Flowcairn:

```bash
node bin/flowcairn.mjs doctor --root PROJECT
node bin/flowcairn.mjs ui --root PROJECT
```

Отсутствующие предпосылки сначала устраняйте по выводу `doctor`. Установка на другую ОС сама по себе не подтверждает поддержку ее sandbox.
