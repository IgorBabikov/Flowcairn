# Установка и первый запуск

Flowcairn — локальный инструмент разработки. Он работает с существующим Git-проектом и выполняет изменения в отдельной рабочей копии.

## Что понадобится

- Node.js 22 и Git; в проекте должен быть первый commit.
- Поддерживаемый менеджер: npm, pnpm либо Yarn 4 с `node_modules`.
- Ваш доступ к Codex на macOS либо OpenAI API на macOS/Linux.
- Docker не нужен для первого запуска, анализа и планирования. Новый проект не запускает свои scripts автоматически. Для проверок непроверенного кода используйте Docker-режим.

Настройки чужого проекта, исходники и ключи нельзя передавать AI без права на такую передачу. Первую проверку выполните на открытом или тестовом проекте.

## Обычная установка из npm

Официальный пакет: [flowcairn](https://www.npmjs.com/package/flowcairn). Актуальную опубликованную версию показывает npm.

В корне вашего проекта:

```bash
npm install -D flowcairn@latest
npx flowcairn
```

Для обычного pnpm-проекта: `pnpm add -D flowcairn@latest`, затем `pnpm exec flowcairn`.

Если это pnpm workspace и команда выполняется из корня, используйте:

```bash
pnpm add -Dw flowcairn@latest
pnpm exec flowcairn
```

`pnpm install flowcairn` не добавляет Flowcairn и не является командой установки. Для Yarn: `yarn add -D flowcairn@latest`, затем `yarn flowcairn`.

Для инструмента разработки можно использовать `npm install -D flowcairn`. Установленная версия фиксируется обычным lockfile, а не ссылкой на ветку Git. Собранный UI входит в пакет, сборка у пользователя не требуется.

## Почему опрос начинается при запуске

Менеджеры пакетов могут запускать install scripts в фоне или запрещать их. Поэтому интерактивный onboarding внутри `npm install` не является надежным общим механизмом. Flowcairn не добавляет обязательный postinstall и не требует специальных флагов: короткая настройка начинается автоматически при первом `npx flowcairn`.

В обычном терминале настройка проведет по четырем коротким шагам:

1. Выбор AI.
2. Способ выбора модели.
3. Подход к тестам.
4. Разрешение на чтение для подготовки плана и подключение Graph к правилам проекта.

Для Codex по умолчанию используется модель и усиление, выбранные в самом Codex: Flowcairn не просит их ID и не переопределяет настройки. OpenAI API требует явный ID модели, потому что не имеет выбора модели в интерфейсе пользователя.

Если найдены Skills с понятными ролями контекста, планирования, тестирования или ревью, Flowcairn подключит до четырех подходящих файлов сам и покажет их в плане. Нестандартные Skills остаются отключенными. Базовые Skills установлены в пакете и используются без копирования в вашу папку инструкций.

Первый запуск использует ручной режим модели и среднее усиление. Расширенные настройки доступны отдельно. После настройки открывается UI; если браузер не открылся, используйте ссылку из терминала. Не публикуйте временную ссылку с session token.

## Первая задача

[Пошаговое руководство](FIRST-TASK.md): три поля → анализ → план → уточнение при необходимости → «Согласен» → реализация и проверки → результат для личного ревью.

Оставьте терминал Flowcairn работающим до завершения. Перед выполнением настроенных проверок подготовьте окружение:

```bash
npx flowcairn checks prepare
```

Обычный запуск не скачивает Docker-образ, не устанавливает пакеты и не запускает scripts из `package.json`. Это позволяет безопасно изучить проект и согласовать план до доверия его исполняемому коду.

`npx flowcairn checks prepare` нужен для Docker-режима. Команда может скачать образ и зависимости, но не запускает AI. `trusted-local` предназначен только для известного проекта и требует отдельного явного подтверждения exact scripts.

Для доверенного внутреннего проекта выбор делается явно:

```bash
npx flowcairn init --check-mode trusted-local --checks typecheck,lint,tests,build --trusted-local-consent
```

Перед этой командой сами просмотрите scripts в `package.json`. Flowcairn закрепит их имена в профиле и привяжет согласие к этому набору; изменение списка отключит локальное выполнение до новой настройки.

## Изменить модель и правила проверки

Закройте UI и выполните:

```bash
npx flowcairn setup
```

Для Codex обычный режим использует его текущую модель и усиление. В `npx flowcairn setup` можно явно задать одну модель и усиление для Flowcairn, если нужно переопределить выбор Codex. Автоматический выбор между разными моделями не включается молча: он появится только после отдельного согласия и проверки доступных моделей аккаунта.

Разрешение чтения хранится локально и связано с профилем. Clone или изменение AI-настроек не переносят его автоматически. Старые планы и результаты сохраняются, но новые права требуют актуальной настройки и версии плана.

## Провайдеры

**Codex:** адаптер рассчитан на macOS и Codex CLI 0.145.0 или 0.154.0 с настроенной сессией. В режиме настроек CLI Flowcairn читает только `model` и `model_reasoning_effort` из пользовательского `config.toml` и передает их явно, не загружая hooks и остальные настройки. Выбор активного чата VS Code не считывается. Выбранная модель должна быть доступна аккаунту. Не отключайте sandbox ради запуска. Проект для Codex не должен находиться в системной временной папке.

**OpenAI API:** задайте `FLOWCAIRN_OPENAI_API_KEY` в окружении процесса через ваш способ управления секретами. Не помещайте ключ в задачу, профиль, Git или screenshot. Для одноразового скрытого ввода в Bash/Zsh:

```bash
read -r -s FLOWCAIRN_OPENAI_API_KEY
export FLOWCAIRN_OPENAI_API_KEY
```

Затем запускайте Flowcairn в том же терминале. Точный ID модели и поддержка выбранного усиления зависят от API; ошибка не скрывается заменой модели. Адаптер обращается к официальному endpoint и не дает модели произвольных tools.

**Claude Code и Cursor:** `flowcairn init` показывает их реальным выбором только после локальной проверки executable и точной версии. Flowcairn наследует модель и усиление из выбранного assistant и не угадывает model ID. Перед каждым новым immutable планом UI показывает отдельное consent: сервис, передаваемые approved scope/instructions/Skills/artifacts, исключения, hashes plan/scope и возможность отмены. Без этого consent CLI не запускается и код не передается.

## Платформы и зависимости

- macOS проверена на реальном хосте. Linux-настройка и контейнерные проверки проверены отдельно; это не доказательство полного внешнего AI-прогона на каждом Linux-хосте.
- Нативный Windows не поддерживается. WSL2 требует Linux Node.js и проект на Linux filesystem; проверки окружения не заменяют реальный приемочный прогон WSL2.
- Yarn 4 поддерживается в ограниченном режиме `nodeLinker: node-modules`. PnP, произвольные plugins и приватные registry не обходятся.
- Проекты с Bun lockfile пока не поддерживаются.
- Lockfiles сохраняются в исходном снимке для воспроизводимых проверок, но не должны расходовать контекст AI.

## Проверить локальную сборку до публикации

Разработчик Flowcairn собирает архив:

```bash
npm ci --ignore-scripts
npm run build
npm pack --ignore-scripts
```

Пользователь готового архива не собирает UI. Из своего проекта можно запустить архив в отдельном окружении npm:

```bash
npm exec --yes --ignore-scripts --package /полный/путь/flowcairn-ВАША_ВЕРСИЯ.tgz -- flowcairn
```

Замените путь фактическим. Этот проверенный способ не добавляет абсолютную `file:`-зависимость в package.json проекта. Если установить локальный архив через `npm install /путь/архив.tgz`, UI работает, но Docker не сможет разрешить внешний абсолютный путь к архиву. Не копируйте произвольные внешние каталоги в Docker ради обхода этой границы.

## Отключить Flowcairn

Закройте UI, завершите или восстановите активные операции, затем:

```bash
npx flowcairn uninstall
```

Команда снимает управляемую интеграцию и удаляет только неизмененные файлы, созданные установкой. Результаты, история, рабочие копии и измененные файлы сохраняются. При сохраненной истории остается и ее исключение из Git.

Зависимость пакета удаляется отдельно: `npm uninstall flowcairn`, `pnpm remove flowcairn` или `yarn remove flowcairn`. Flowcairn перечисляет остатки честно; полное удаление любой истории одной командой не обещается. Для предварительной проверки есть `uninstall --dry-run`.

## Обновления

`npx flowcairn update` явно проверяет метаданные официального пакета в npm. Исходники и ключи не отправляются; зависимости и активный план не меняются. Обновление по новостям AI и автоматическое переписывание workflow не выполняются.
