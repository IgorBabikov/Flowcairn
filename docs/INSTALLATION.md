# Установка и первый запуск

Текущий исполнитель Flowcairn работает с существующим Git-проектом, сохраняет контракт задачи и меняет исходники в отдельной рабочей копии.

## Подготовка

- Node.js 22, Git и первый commit проекта.
- Корневой `package.json`; npm, pnpm или Yarn 4 с `node_modules` и согласованным lockfile.
- Установленный и авторизованный AI CLI: Codex на macOS либо Claude Code/Cursor на macOS или Linux.
- Право передавать выбранные файлы используемому AI-провайдеру.

Docker нужен только для режима проверок `hardened`. В режиме `none` scripts проекта не выполняются. `trusted-local` разрешает их запуск с правами вашей учетной записи и подходит только для доверенного кода.

## Текущая версия из `main`

Пока новая версия не опубликована в npm, запустите ее из исходников:

```bash
git clone https://github.com/IgorBabikov/flowcairn.git
cd flowcairn
npm ci
npm run build
```

Затем перейдите в каталог своего проекта и запустите `node /путь/к/flowcairn/bin/flowcairn.mjs`. Укажите абсолютный путь к клонированному репозиторию. Исходники Flowcairn не копируются в проект.

## Опубликованный пакет

Из корня проекта:

```bash
npm install -D flowcairn
npx flowcairn
```

Эквиваленты:

| Проект | Установка | Запуск |
| --- | --- | --- |
| pnpm | `pnpm add -D flowcairn` | `pnpm exec flowcairn` |
| Корень pnpm workspace | `pnpm add -Dw flowcairn` | `pnpm exec flowcairn` |
| Yarn 4 | `yarn add -D flowcairn` | `yarn flowcairn` |

Менеджер фиксирует установленную версию в lockfile. Собранный UI входит в пакет. Доступную опубликованную версию показывает [npm](https://www.npmjs.com/package/flowcairn); она может отставать от `main`.

## Первоначальная настройка

Первый запуск Flowcairn открывает настройку. Для установленного пакета отдельно ее можно начать командой `npx flowcairn init`. Install hook для опроса не используется.

Мастер задает AI-клиент и модель, политику добавления тестов, режим выполнения scripts и разрешение чтения. Подключение управляемых правил к существующим инструкциям согласуется отдельно. Найденные подходящие project Skills показываются и закрепляются в профиле.

Flowcairn сохраняет `.flowcairn.json`, локальное состояние в `.ai-orchestrator/` и исключает его через `.git/info/exclude`. Повторный `init` сохраняет существующий профиль; конфликтующий чужой state не перезаписывается. После clone профиль не переносит локальное согласие на передачу данных.

UI открывается в браузере. Если автоматическое открытие не сработало, используйте локальную ссылку из терминала. Оставьте процесс работающим; временную session-ссылку не публикуйте.

## Проверки проекта

`init` предлагает найденные conventional scripts. Выберите `none`, `hardened` или `trusted-local` и проверьте показанный набор команд. Выбор «добавлять тесты» сам по себе не разрешает запуск scripts.

Для Docker-режима после настройки подготовьте образ:

```bash
npx flowcairn checks prepare
```

Подготовка может скачать образ и зависимости. Она не вызывает AI и не доказывает прохождение проверок задачи.

## Запуск и изменение настроек

[Первая задача](FIRST-TASK.md): описание → контракт и план → согласование → исполнение → доказательства требований → PROVEN.

Для изменения настроек остановите процесс Flowcairn и выполните:

```bash
npx flowcairn setup
```

Модели, чтение и запуск scripts имеют отдельные настройки и согласия. Смена конфигурации не выдает новые права старому плану. [Поля профиля](CONFIGURATION.md) · [AI-клиенты](AI-HARNESS-INTEGRATION.md).

## Запуск локальной сборки

Из исходного репозитория Flowcairn под Node.js 22:

```bash
npm ci --ignore-scripts
npm run build
npm pack --ignore-scripts
```

Готовый архив можно запустить из тестового проекта без добавления абсолютной `file:`-зависимости:

```bash
npm exec --yes --ignore-scripts --package /path/to/flowcairn-VERSION.tgz -- flowcairn
```

Замените путь и VERSION значениями созданного архива. Наличие архива не означает публикацию в npm. Абсолютные внешние зависимости проекта нельзя копировать в Docker обходом разрешенных manifests.

## Обновление и удаление

`npx flowcairn update` проверяет метаданные npm. Команда не устанавливает новую версию, не отправляет исходники и не меняет активную задачу. Обновляйте зависимость обычным менеджером пакетов.

После остановки Flowcairn можно предварительно проверить удаление:

```bash
npx flowcairn uninstall --dry-run
npx flowcairn uninstall
```

Удаляются только неизмененные файлы и управляемые блоки установки. Измененные файлы, результаты, история и рабочие копии сохраняются. Зависимость удаляется отдельно: `npm uninstall flowcairn`, `pnpm remove flowcairn` или `yarn remove flowcairn`.
