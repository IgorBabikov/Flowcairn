# Текущие изменения

Эти изменения описывают новую рабочую версию; публикация пакета выполняется отдельно.

- `0.2.22` в исходной ветке: исправлен запуск AI для больших наборов разрешенных путей; лимит управляющего аргумента остается ограниченным и проверяется до запуска.
- В главном экране причины остановки называют проверки и требования человеческим языком. README показывает план, три проверяемых критерия и устаревание результата на понятной задаче восстановления доступа.
- Главный экран показывает задачу, требования, доказательства, проблемы и расход; граф доступен как подробное представление исполнения.
- Неизменяемый Task Contract сохраняет цель, обязательные требования, способы проверки и связи с работой.
- PROVEN вычисляется по полному покрытию обязательных требований актуальными доказательствами. Общий AI pass или завершенные nodes недостаточны.
- Проверки привязаны к состоянию результата; после изменения исходников evidence становится stale и сертификат отзывается.
- Ошибки проверок и обязательных assessments создают structured findings и запускают ограниченный repair/reverification в рамках согласованных прав.
- Личная приемка привязана к конкретному требованию, актуальному result hash, плану и revision.
- Контекст реализации выбирается по требованиям, путям и зависимостям; реальные provider counters отделены от неизвестного расхода.
- Большие словари можно переносить по ключам с точной проверкой исходных значений; review видит проверяемые изменения без копирования всего файла.
- После прерванного планирования актуальный успешный анализ используется повторно, если исходники не менялись.
- Смешанные обязанности runtime, provider runner, Docker stop proofs, Orchestrator, UI и установки выделены в отдельные модули.
- Документация и Skills описывают действующую модель доказуемой работы; прежний нормативный graph-first документ удален.
