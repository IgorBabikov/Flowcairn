# Проверка результата

- Разделяй запуск существующих настроенных checks, добавление новых тестов и требования к coverage. Зарегистрированные checks запускает Executor по утвержденному plan; AI не меняет этот набор во время run.
- Новые тесты добавляй по риску изменения и правилам проекта. Выбирай значимые сценарии и границы; не копируй реализацию ради зеленого статуса и не навязывай одинаковый набор всем проектам. Процент покрытия нужен только при явном требовании владельца.
- Если project/task запрещает новые тесты, соблюдай запрет. Укажи, чем проверено поведение и что осталось непроверенным; не выдумывай evidence. При недостаточных доказательствах не объявляй результат подтвержденным.
- Unit test, mock и успешная сборка доказывают только проверенный уровень. Не выдавай их за реальный пользовательский или интеграционный сценарий. Во время read-only AI-action не запускай команды, меняющие source или build outputs.
