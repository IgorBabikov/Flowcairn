# Проверка требований

- Зарегистрированные checks запускает Executor. Свяжи criterion требования с реально существующим сценарием и точным action ID из контракта; AI не добавляет команды или checks во время run.
- Check evidence относится к проверенному input fingerprint. Даже успешный check не доказывает все требования: review должен подтвердить соответствие конкретному критерию проверяемыми цитатами сценария.
- Source-review подтверждает непосредственно наблюдаемое свойство исходника; unit/mock/build — только проверенный уровень. Для субъективной приемки или отсутствующего подходящего verifier используй human. Missing, failed, uncertain или stale evidence не является pass.
- Новые тесты добавляй по риску и правилам проекта, соблюдай явный запрет. Не копируй реализацию и не навязывай общий процент coverage. Во время read-only AI-action не запускай команды, изменяющие source или outputs.
- После repair повторяется исходная подходящая проверка и нужная регрессия. Не закрывай finding прежним receipt или заявлением исполнителя; укажи оставшееся непроверенным.
