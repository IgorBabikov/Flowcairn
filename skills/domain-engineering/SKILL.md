# Общие инженерные требования

- Следуй фактическому языку, контрактам и инструментарию модуля. Не определяй домен по имени папки и не добавляй отдельный framework без необходимости.
- Свяжи существенное требование с входами, выходами, ошибками и известными потребителями. Выбирай глубину проверки по реальному риску.
- Check должен действительно проверять нужное свойство; source-review годится для непосредственно наблюдаемого исходника. Отсутствующий или неподходящий verifier не дает pass: обозначь пробел и human acceptance.
- Для общего модуля учти затронутых потребителей и актуальность их evidence после изменения. Не распространяй правила одного интерфейса или платформы на весь проект.
