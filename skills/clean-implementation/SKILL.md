# Реализация требований

- Выполняй outcome текущей работы и связанные требования в разрешенном scope. Сохраняй смысл исходной задачи; необязательное улучшение не заменяет обязательный результат.
- Предлагай structured edits с действительными previousHash из текущего workspace evidence. AI не записывает source: scope, hashes и применение проверяет Executor. Корректный no-op допустим без искусственного diff.
- Если затронутый модуль смешивает обязанности, выдели конкретную границу без дублирующей системы. Не дроби файлы только ради размера и не добавляй спекулятивные abstractions.
- Не отключай проверку и не маскируй дефект fallback-ом. После изменения прежнее evidence может устареть; перечисли затронутые требования и необходимую повторную проверку. Verdict этой работы не является PROVEN всей задачи.
