# flowcairn

Это отдельный open-source инструмент. Русский язык для документации и интерфейса, machine IDs сохраняются.

- Актуальное поведение описано в docs/HOW-FLOWCAIRN-WORKS.md и docs/ARCHITECTURE.md. Проверяй эти документы по работающему коду; не восстанавливай старую graph-first концепцию.
- Executor владеет состоянием и правами. Главный UI — задача и ее результат; ReactFlow показывает структуру исполнения в расширенном представлении.
- Завершенность определяется обязательными требованиями: каждое связано с работой, допустимой проверкой и актуальным evidence. Общий AI pass или passed node не дают PROVEN.
- Разделяй runtimeRoot (пакет) и projectRoot (проект пользователя). Не записывай исходники пакета в чужой проект.
- Сохраняй immutable hashes, trusted registry, permissions, receipts, gates, idempotency и failed/uncertain.
- Skills и правила качества: docs/SKILLS.md. Project Skills действуют только на выбранных этапах и в выбранных областях. Покрытие обязательных требований доказательствами обязательно; процент test coverage сам по себе не является критерием завершения.
- Сохраняй source-bound evidence, stale semantics, structured findings и ограниченный repair/reverification. Missing verifier и неопределенность не превращаются в PASS.
- Не оставляй перегруженные модули: разделяй смешанные обязанности, сохраняй единый источник состояния и проверяй поведение после декомпозиции.
- Не включай личные инструкции, абсолютные пользовательские пути, приватные данные, токены или историю внутренних запусков в пакет.
- Не обнуляй чужие Git changes, AGENTS или hooks. Установка должна быть повторяемой и безопасно отказываться от конфликта.
- Работай в назначенных файлах, не отменяй чужие правки. Source changes проверяй unit/integration/typecheck; UI проверяй в браузере.
- Команды и платформы в README должны пройти fresh-install verification. Не обещай непроверенную поддержку.
- Публикация, push, merge и другие внешние действия требуют явного разрешения на конкретное действие; успешная локальная проверка его не заменяет.
