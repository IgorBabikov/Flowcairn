# Дополнительный учебный режим нативного клиента

Архитектурное решение для S3: отдельный opt-in `native-client-learning`, первоначально для Cursor. Это не переименование неподтвержденного `material-only` в PASS. Строгие профили Codex/Claude сохраняются. Автоматического fallback между уровнями или провайдерами нет.

## Пользовательский результат и граница

После отдельного явного разрешения пользователь получает обычный разбор и вопросы через выбранный Cursor. Flowcairn передает сохраненный материал и проверяет структуру/цитаты/версию результата. Cursor сохраняет свои настройки и штатные permission controls. Ask/sandbox не дают основания обещать отсутствие любых hooks/MCP/дополнительного контекста или всех внешних эффектов.

Раскрытие перед разрешением: «Flowcairn передаст Cursor сохраненный код этой задачи. Cursor может добавить контекст из своих правил и использует собственные разрешения. Flowcairn не изолирует все действия нативного клиента. Настроенные автоматические действия проверяются отдельно; неизвестные действия или новые получатели данных не разрешаются этим согласием».

Default — выключено. Пользователь не должен включать его заново для каждого вопроса, пока выбранный профиль, инструмент, область и текст раскрытия не изменились. Включение не дает прав Executor на запись исходников, commit, публикацию или оплату.

## Детерминированные условия допуска

- Реально поддержанные и закрепленные CLI/mode/sandbox/permissions, без force, approve-all и обхода native policy.
- Проверены выбранный профиль, текущая авторизация и доступные источники конфигурации. Account/effective policy отмечаются только по полученным фактам; неизвестные значения не фабрикуются.
- Известные локальные/managed hooks, MCP и actions требуют отдельной оценки. Неизвестная динамическая policy, неразрешенная запись, публикация, команда или новый получатель закрывают конкретный профиль/действие. Общая галочка не разрешает неизвестные эффекты.
- Только после подходящего inspection доступно согласие. Недоступный inspection дает конкретную причину и не включает режим. Нельзя оставлять успешную кнопку поверх blanket denial, выдавая это за работающую интеграцию.
- Перед prepare/GO/worker повторно проверяются связанные настройки и текущий выбор CLI. Изменение закрывает ожидающий запуск. Исторические согласия/receipts не переписываются.
- Вход Flowcairn — только разрешенные saved material/method/question. Дополнительный native context не становится evidence. Выход — только validated JSON с точными source anchors.
- Проверка проекта до/после вызова является наблюдением, а не предотвращением всех эффектов. Наблюденная неожиданная запись/source drift дает failed/uncertain/stale; автоматического reset/retry нет. PROVEN не повышается учебным результатом.

## Минимальные привязки

Inspection и consent должны связывать provider, `boundaryTier`, disclosure version/hash, selected client configuration/profile, CLI/toolchain, доступную identity account, область источников и разрешенные действия `generate-lesson`/`ask-lesson`. Consent сохраняет actor/time и hash проверенного inspection. Для недоступной account/policy identity не подставлять выдуманное значение; допустимость такого профиля остается отдельным подтвержденным gate.

Provider binding учебной job получает только необходимые optional hashes/tier, чтобы старые jobs сохранили прежние bytes и hashes. Команда/mode/args связаны существующим commandHash. Raw credentials/settings не передаются модели и не пишутся в отчеты. Реальные reported model/effort отличаются от намерения `provider-default`.

## Разделение работ

- Provider engineer: точный native inspection/eligibility, command/worker/JSON parsing, source-change observation и meaningful protocol/fault tests. Сперва закрыть S3-01/S3-02 предыдущего среза.
- Settings engineer: после согласования интерфейса inspection — существующий onboarding/settings путь, отдельное явное согласие и его сохранение/отзыв; не новый executor или task database.
- Root: интеграция DTO/границ, независимое review, единый пользовательский сценарий и честная матрица доказательств.

Этот контракт не является доказательством готовности Cursor. Положительный путь должен работать на допустимом native profile и пройти соответствующие проверки. Если текущая версия не дает проверить требуемый профиль, ограничение остается открытым R07, а не превращается в декларацию поддержки.
